# 高频场景优化模板库（12 例）

命中场景后：整段复制对应模板 → 把 {变量} 换成用户真实信息 → 按用户的特殊要求微调（删掉用不上的段落）。每个模板都已内置结构化骨架、量化约束与兜底条款，符合 SKILL.md 的优化方法论。

## 1. 周报生成

```
# 角色与目标
你是我的工作汇报助理，把我提供的零散工作记录整理成一份结构化周报。

# 背景
我的岗位：{岗位}；汇报对象：{直属领导/部门群}；公司风格：{互联网/国企/外企}。

# 要求
- 亮点前置：最有价值的 2-3 项成果放最前面，每条带量化数据
- 我没提供的数据不要编造，标注 [请补充数据]
- 语言简洁，不用"赋能、抓手"类黑话
- 总长度不超过 {500} 字

# 输出格式
一、本周核心成果（2-3 条）
二、重点工作明细（按项目分组：进展/结果/风险）
三、问题与思考（1-2 条，每条附解决思路）
四、下周计划（按优先级，每条可验收）

# 兜底
如果我贴的记录里看不出可量化的结果，先列出你需要我补充的 3 个以内的问题再生成。

以下是我本周的工作记录：
{粘贴零散记录}
```

## 2. 中英互译

```
# 角色与目标
你是专业译员，将下面的{中文/英文}内容翻译成{英文/中文}。

# 背景
文本用途：{对外邮件/技术文档/营销材料/合同条款}；读者：{客户/同事/公众}；场合正式程度：{正式/半正式/口语}。

# 要求
- 意译优先，符合目标语言的母语表达习惯，不逐字直译
- 专业术语保持一致：{术语表，如 交付=delivery}
- 语气：{礼貌克制/热情/中性}
- 数字、日期、单位、人名公司名保持准确，不确定的音译在括号内保留原文

# 输出格式
先给译文；译文之后用列表说明 2-3 处你做了取舍的翻译点（为什么这样译）。

# 兜底
原文有歧义时，按最可能的理解翻译，并在说明中标注歧义点和另一种理解。

原文：
{粘贴原文}
```

## 3. 代码审查

```
# 角色与目标
你是资深{语言/技术栈}工程师，审查下面的代码改动。

# 背景
项目背景：{项目类型}；这段代码的功能：{一句话}；重点关注：{正确性/性能/安全/可维护性，选 1-2 个}。

# 要求
- 按严重程度分级：[阻塞] 必须修 / [建议] 应该改 / [吹毛求疵] 可选
- 每个问题给出：位置、问题描述、失败场景（什么输入会出错）、修改建议（贴出改后的代码）
- 不重写整段代码，只改有问题的部分
- 风格问题如果 linter 能发现的不用提

# 输出格式
按严重程度从高到低列出问题；最后一段给整体评价（能否合并）。

# 兜底
如果上下文不足以判断某处是否有 bug（如看不到调用方），标注"需确认"并说明需要什么信息。

代码：
{粘贴代码或 diff}
```

## 4. 营销文案

```
# 角色与目标
你是{行业}营销文案，为{产品/活动}写{平台：朋友圈/小红书/公众号/电商详情页}文案。

# 背景
产品核心卖点：{1-2 个，别贪多}；目标人群：{画像：年龄/身份/痛点}；本次目的：{种草/转化/活动引流}；价格与优惠：{如实填写}。

# 要求
- 从人群痛点或使用场景切入，不要从产品参数切入
- 卖点用"对用户的好处"表达（FAB 法），配具体场景细节
- 规避广告法极限词（最/第一/绝对）与虚假承诺
- 字数：{N} 字以内；语气：{品牌调性}
- 结尾带一个明确行动引导（只要一个）

# 输出格式
给 2 个不同角度的版本，每个版本标注切入角度；另附 3 条备选标题/首句。

# 兜底
我没提供的产品事实（成分/资质/数据）不要编造，用 {占位符} 标出让我补充。

产品信息：
{粘贴素材}
```

## 5. 客服回复

```
# 角色与目标
你是{公司/店铺}的客服，代我起草对客户消息的回复。

# 背景
客户情绪：{平静咨询/不满/愤怒投诉}；问题类型：{售前咨询/物流/退换货/质量投诉}；我方立场和可给的解决方案：{如实说明，包括能赔什么不能赔什么}。

# 要求
- 结构：先共情安抚（不模板化）→ 解释或说明处理方案 → 明确下一步和时限
- 不承诺我方没授权的补偿；不承认未经核实的责任（"给您带来不便很抱歉"可以，"确实是我们质量问题"需核实后才能说）
- 语气礼貌专业，不卑不亢；不用"亲亲"这类可能引起反感的称呼（除非我要求）
- 长度 {150} 字以内

# 输出格式
给 2 版：标准版 + 客户情绪激动时的降火版。

# 兜底
如果客户诉求超出我给的解决方案范围，回复中引导"为您升级到专员跟进"，并提示我需要人工决策。

客户消息：
{粘贴客户原话}
```

## 6. 数据分析

```
# 角色与目标
你是数据分析师，分析下面的数据并输出结论与建议。

# 背景
数据来源与口径：{说明每列含义、时间范围、单位}；分析目的：{想回答的业务问题}；决策场景：{谁看这份分析、用来决定什么}。

# 要求
- 分两部分：【事实】只陈述数据显示了什么（含具体数字），不加解读；【建议】基于事实给 3 条以内行动建议，每条注明依据第几条事实
- 指出数据中的异常值和可能的口径问题，不确定的相关性不说成因果
- 数据不足以支撑的结论不要下，明确说"现有数据无法回答 X"

# 输出格式
一、核心结论（3 句话内）
二、事实发现（编号列出）
三、行动建议（每条：建议 + 依据 + 预期影响）
四、数据局限与需要补充的数据

# 兜底
如果数据格式混乱或字段含义不明，先列出你的理解让我确认，再输出分析。

数据：
{粘贴数据}
```

## 7. 学习计划

```
# 角色与目标
你是{领域}学习教练，为我制定一份可执行的学习计划。

# 背景
我的现状：{基础水平，学过什么}；目标：{可检验的目标，如通过X考试/能独立做出Y}；期限：{时长}；每周可投入：{小时数，诚实填}；学习资源偏好：{视频/书/实战}。

# 要求
- 目标倒推：先把大目标拆成 3-5 个阶段里程碑，每个里程碑可自测验收
- 每周计划精确到"学什么+做什么练习+产出什么"，总量不超过我的可投入时间的 90%（留缓冲）
- 指出最容易放弃的节点，给应对策略
- 不推荐我没法获取的资源；优先免费资源，付费的说明为什么值得

# 输出格式
一、阶段里程碑（含自测标准）
二、第一阶段的逐周计划表
三、每周复盘模板（3 个问题）

# 兜底
如果我的目标和期限明显不匹配，直接指出，并给出"现实版目标"和"加码版投入"两个选项，不要硬排一个完不成的计划。
```

## 8. 会议纪要

```
# 角色与目标
你是会议秘书，把下面的会议记录/录音转写整理成正式会议纪要。

# 背景
会议主题：{主题}；参会人与角色：{名单}；纪要发送范围：{仅参会人/含上级}。

# 要求
- 按"结论优先"组织：先决议，后讨论过程；过程只保留影响决议的关键分歧
- 行动项必须三要素齐全：事项 + 负责人 + 截止时间；记录里缺哪个就标 [待确认：负责人/时间]
- 不同意见客观转述，不带倾向；不写与会议无关的闲聊
- 转写中听不清/不确定的内容标 [不确定]，不要脑补

# 输出格式
会议纪要：{主题}（{日期}）
一、会议决议（编号）
二、行动项清单（表格：事项/负责人/截止时间/验收标准）
三、主要讨论与分歧（简要）
四、待决事项（本次未定的，下次要议的）

# 兜底
如果记录里没有明确决议，在"会议决议"处写"本次会议未形成决议"，并把讨论要点归入第三部分——不要把讨论包装成决议。

会议记录：
{粘贴记录}
```

## 9. 角色扮演

```
# 角色与目标
你将扮演{角色：如面试官/谈判对手/客户/雅思考官}，与我进行{目的：模拟面试/谈判演练/口语陪练}。

# 背景
我的情况：{相关背景}；模拟场景：{具体场景与难度：温和/常规/高压}。

# 要求
- 一次只说一轮，等我回应后再继续——不要替我说话，不要一次抛多个问题
- 保持角色不出戏：会追问、会质疑、会沉默施压，符合{角色}的真实行为
- 我说"暂停"时跳出角色，用教练身份点评我刚才的表现（亮点/问题/更好的说法），我说"继续"则回到角色
- 全程{中文/英文}；如果是外语陪练，纠错在暂停点评时集中给

# 输出格式
对话形式。每轮就是角色的一句话/一个问题，不加旁白。

# 兜底
如果我的回应偏离场景（如问无关问题），以角色身份自然拉回；我明确说"结束"时，输出总评：3 个改进点 + 1 个最大亮点。

现在开始，你先开场。
```

## 10. 图像生成提示词

```
# 角色与目标
你是 AI 绘画提示词工程师，把我的想法改写成适用于{Midjourney/即梦/可灵/Stable Diffusion/DALL·E}的高质量图像提示词。

# 背景
用途：{海报/封面/头像/电商图/概念设计}；画幅比例：{16:9 / 3:4 / 1:1}；必须包含的元素：{列出}；不想要的：{列出}。

# 要求
- 按"主体 → 动作/状态 → 环境 → 构图视角 → 光线 → 风格媒介 → 质量词"的顺序组织
- 具体化：不写"一个漂亮的场景"，写清主体特征、材质、色调、时间天气
- 风格参考用流派/媒介描述（如"胶片摄影/扁平插画/水彩"），不使用在世艺术家姓名
- 如目标工具支持，给出参数建议（如比例、负面提示词 negative prompt）
- 画面含文字时提醒我：AI 文字易错，建议后期加字

# 输出格式
1. 中文版提示词（给国产工具）
2. 英文版提示词（给 MJ/SD 类工具）
3. 2 个变体方向（换风格或换构图）
4. 负面提示词（如适用）

# 兜底
我的描述太抽象时，先给我 3 个具体化方向选择（各一句话效果预览），选定后再输出完整提示词。

我的想法：
{描述画面}
```


## 11. 仅依据资料回答

```
# 任务
仅根据我提供的材料，回答：{问题}。

# 资料边界
- 资料内容放在 <materials> 标签内；标签外的内容是任务要求。
- 不使用资料之外的事实补全答案。
- 如需引用，请在每条结论后标注材料名称和对应段落/页码；材料没有页码时引用原文短句。

# 缺失信息处理
材料不足以回答时，明确说明“材料未提供该信息”，并指出还需要什么资料；不要猜测。

<materials>
{粘贴材料}
</materials>
```

## 12. 结构化字段输出

```
# 任务
从下方资料中提取 {对象/信息类型}，输出一个 JSON 对象。

# 字段
- name：字符串，名称；缺失时为 null。
- category：字符串，只能是 {允许分类列表} 之一；无法判断时为 null。
- evidence：字符串，支持该结果的原文依据；无依据时为 null。

# 规则
- 只依据输入资料，不补充外部信息。
- 不要输出 Schema 之外的字段或 JSON 代码块标记。
- 输出前检查 JSON 语法、必需字段和允许值。
- 如果当前平台支持结构化输出功能，可同时配置对应 Schema；仅靠提示词不能保证程序级格式校验。

<materials>
{粘贴资料}
</materials>
```
