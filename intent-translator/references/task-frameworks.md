# 任务类型框架库

按任务选择框架。每个框架都是可选字段库，不是固定问卷。只保留与当前任务相关的字段。

## 1. AI Coding / 开发任务

建议字段：
- 目标：希望完成什么。
- 背景：为什么要做。
- 项目现状：已知技术栈、模块、运行环境。
- 问题表现：实际发生了什么。
- 复现步骤：如何稳定复现。
- 期望行为：正确结果是什么。
- 修改范围：允许修改哪些部分。
- 保留项：哪些代码、接口、行为不可改变。
- 技术约束：兼容性、依赖、性能、安全等。
- 执行方式：先分析、先给方案，还是直接实施。
- 验收：测试、构建、运行或人工检查标准。
- 交付：修改摘要、文件清单、测试结果、风险说明。

注意：
- 未知项目事实不要编造。
- 可要求执行者先阅读项目结构、相关代码和现有约定。
- 用户要求只读审计时，明确禁止修改文件。
- 用户允许实施时，也应限定修改范围并要求报告实际变更。
- 不要把“修复问题”扩展成全面重构。

## 2. 产品需求 / 功能设计

建议字段：
- 业务背景；
- 目标用户；
- 用户场景；
- 当前痛点；
- 目标和成功标准；
- 功能范围；
- 业务规则；
- 主流程；
- 异常与边界处理；
- 权限与角色；
- 数据及状态；
- 非目标（本次不做什么）；
- 优先级；
- 验收标准。

注意区分用户问题、产品目标和具体解决方案。用户提出的方案可能只是初步想法，不应未经判断就视为唯一实现方式。

## 3. Skill / Agent / 插件设计

建议字段：
- 定位；
- 目标用户；
- 触发条件；
- 典型输入；
- 核心能力；
- 工作流程；
- 工具及外部依赖；
- 输入输出；
- 文件结构；
- 失败与降级处理；
- 安全边界；
- 测试场景；
- 上架或交付标准。

注意：
- 不为了覆盖更多场景而无限增加能力。
- 触发条件要覆盖自然语言表达，但避免误触发普通任务。
- 约束应服务于实际目标，避免重复、冲突和不必要的强制要求。
- 明确 Skill 自身能做什么、依赖宿主提供什么。

## 4. UI / UX / 视觉设计

建议字段：
- 产品背景；
- 页面或模块；
- 目标用户；
- 当前问题；
- 核心任务路径；
- 信息层级；
- 布局要求；
- 视觉风格；
- 交互要求；
- 响应式要求；
- 保留项；
- 禁止改动项；
- 参考材料；
- 交付物；
- 验收标准。

注意：
- 参考图说明的是可借鉴部分，不代表全部照搬。
- 区分视觉偏好和功能要求。
- 不要把“更好看”作为唯一验收标准。

## 5. 竞品调研 / 市场研究

建议字段：
- 决策目的；
- 研究问题；
- 竞品或研究对象；
- 地区；
- 时间范围；
- 用户群体；
- 研究维度；
- 证据来源；
- 数据口径；
- 分析方法；
- 对比维度；
- 结论；
- 机会与风险；
- 不确定性；
- 交付形式。

注意：
- 涉及最新信息时要求核验原始来源和发布日期。
- 关键数字标注年份、单位、地区和统计口径。
- 区分事实、推断和建议。
- 不将单个案例夸大为普遍趋势。

## 6. Bug / 产品问题反馈

建议字段：
- 标题；
- 产品版本；
- 设备和环境；
- 前置条件；
- 复现步骤；
- 实际结果；
- 预期结果；
- 复现频率；
- 影响范围；
- 日志或截图；
- 已尝试排查；
- 可能原因。

注意：
- 先描述事实，再写推测原因。
- 不把“怀疑是模型问题”写成已确认根因。
- 问题标题尽量描述现象和对象。
- 用户需要简短反馈时，优先控制长度。

## 7. 工作沟通 / 汇报

建议字段：
- 接收对象；
- 沟通渠道；
- 沟通目的；
- 当前背景；
- 已确认事实；
- 核心观点；
- 需要对方理解或决定的事项；
- 希望对方采取的行动；
- 语气；
- 长度。

注意：
- 事实、判断、建议分开。
- 不擅自增加指责、承诺或未经证实的归因。
- 保留用户希望表达的立场。
- 根据接收对象选择自然程度，不要过度公文化。

## 8. 计划 / 流程 / 项目推进

建议字段：
- 目标；
- 当前状态；
- 范围；
- 阶段；
- 任务；
- 依赖；
- 负责人；
- 时间节点；
- 资源；
- 风险；
- 决策点；
- 完成标准；
- 汇报机制。

注意：
- 未知负责人和日期不要虚构。
- 识别前置依赖和关键路径。
- 区分已确定安排与建议排期。

## 9. 内容创作 / 文案

建议字段：
- 内容目的；
- 目标读者；
- 发布渠道；
- 核心信息；
- 语气和风格；
- 必须包含的信息；
- 禁止出现的表达；
- 长度；
- 格式；
- 行动引导；
- 参考材料。

注意：
- 不把用户的参考文案当作必须照搬的模板。
- 保留品牌、产品和事实信息。
- 用户需要多版本时再提供多版本。

## 10. 数据分析 / 报告

建议字段：
- 分析目的；
- 数据来源；
- 时间范围；
- 指标定义；
- 维度；
- 口径；
- 分析问题；
- 方法；
- 预期图表或输出；
- 结论要求；
- 局限性。

注意：
- 不猜测缺失数据。
- 指标口径不明确且影响结论时应追问。
- 区分相关性与因果关系。
- 结果应可追溯到数据和计算口径。
