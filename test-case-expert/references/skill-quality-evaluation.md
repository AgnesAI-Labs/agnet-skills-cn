# AI Skill 输出质量与评估方法

## 1. 评估原则

AI 输出通常具有非确定性。除非输出是严格结构化数据或明确要求固定文本，否则不要要求逐字完全一致。应评估关键行为、内容要素、事实依据和任务结果。

评估必须基于 Skill 的目标和用户需求，不能将评估者偏好冒充产品要求。

## 2. 评估维度

按任务选择：

- 任务完成度：是否解决用户提出的问题。
- 准确性：事实、计算、数据和引用是否正确。
- 完整性：是否覆盖必要要素。
- 相关性：是否聚焦目标。
- 逻辑性：结论是否由证据支持。
- 专业性：是否符合领域要求。
- 可执行性：是否能直接使用或落实。
- 结构规范：是否符合规定格式。
- 一致性：前后内容、数字、术语是否冲突。
- 约束遵循：是否遵守 Skill 和用户要求。
- 来源质量：是否使用真实、可核验且适用的来源。
- 风险控制：是否妥善处理不确定性和安全边界。

## 3. 评估方式

### 精确规则断言
适用于：
- JSON Schema 校验；
- 必需字段、文件、链接是否存在；
- 数字范围、状态码、退出码；
- 指定工具是否调用；
- 是否产生预期状态变化。

### 关键词/结构断言
适用于必要字段、章节、标记、特定术语，但不能单独作为复杂语义质量判断。

### 语义评分
适用于任务完成度、相关性、逻辑性、专业性等。评分时应提供明确 rubric、正反例或关键检查点。

### 人工评估
适用于审美、复杂专业判断、真实可用性、主观体验和高风险结论。

### 混合评估
优先采用“规则断言 + 语义评分 + 必要人工复核”，并记录各自证据。

## 4. 评分量表示例

可采用 0–4 分：
- 0：完全未完成/严重违反要求；
- 1：主要目标未达成，仅有少量相关内容；
- 2：部分达成，存在明显遗漏或错误；
- 3：基本达成，少量非关键问题；
- 4：完整达成，符合所有关键标准。

评分前必须定义该用例的具体评分标准。不同 Skill 不应机械使用相同权重。

## 5. AI 输出质量用例写法

每条用例应明确：
- 用户输入和上下文；
- 关键预期行为；
- 必须包含的内容要素；
- 不允许出现的错误；
- 证据要求；
- 评分标准或通过阈值；
- 是否需要人工评估。

## 6. 稳定性评估

同一输入多次运行时：
- 比较关键事实、结构和任务结果；
- 允许措辞差异；
- 检查关键断言是否稳定；
- 记录模型、平台、配置和时间；
- 样本次数应按风险决定，不得凭一次运行宣称稳定。

## 7. 来源与事实核验
涉及事实、法律、医学、金融、实时数据或外部研究时：
- 检查来源是否真实存在；
- 检查发布日期、适用地区和时效；
- 区分事实、推断和不确定信息；
- 不得把模型生成的引用当作真实来源；
- 对无法独立核验的内容标记待核查。
