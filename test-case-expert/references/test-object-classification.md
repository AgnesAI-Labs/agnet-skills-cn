# 测试对象识别与拆分

## 目标

先判断“测试什么”，再决定“如何测试”。一个对象可以同时属于多个类型，不得强制单选。

## 对象分类

### 1. 软件与应用
- Web、桌面、移动端、浏览器扩展、客户端。
- 重点：页面、交互、业务流程、状态、权限、数据、兼容、性能、安全、安装升级。

### 2. 功能与业务逻辑
- 单个功能、业务规则、用户故事、审批流、计算规则。
- 重点：正常/反向流程、条件组合、状态变化、角色差异、数据规则。

### 3. 代码与脚本
- 函数、模块、命令行工具、Python/JS/Shell 等。
- 重点：参数、返回值、分支、异常、资源、文件、依赖、环境、幂等性。

### 4. API 与接口
- REST、GraphQL、RPC、WebSocket、Webhook。
- 重点：协议、参数、响应、认证授权、错误码、限流、并发、幂等、契约。

### 5. 数据库与数据处理
- SQL、数据导入导出、ETL、同步、清洗、迁移。
- 重点：数据类型、约束、事务、重复/缺失/异常数据、一致性、回滚、批量处理。

### 6. 自动化工作流与插件
- RPA、Dify 工作流、MCP Server、插件、连接器、节点式自动化。
- 重点：触发、节点输入输出、分支、工具权限、连接状态、重试、超时、恢复、副作用。

### 7. AI Agent 与 Skill
- Agent、Skill、提示词、RAG、工具使用、多轮对话、智能工作流。
- 重点：触发、指令遵循、任务规划、上下文、工具、文件、输出质量、幻觉、安全、稳定性。

### 8. 系统集成与端到端
- 多模块、多服务、多平台的完整链路。
- 重点：接口契约、数据流、身份传递、异步消息、失败恢复、端到端结果。

## 复合对象拆分

当对象包含多个子系统时，按以下方式拆分：
1. 列出组件/模块及职责。
2. 标记模块之间的输入、输出和依赖。
3. 为每个模块设计适用的单元/组件测试。
4. 为关键交互设计集成测试。
5. 为用户核心业务路径设计端到端测试。
6. 对跨模块风险设计故障恢复、数据一致性和权限测试。

示例：AI 桌面 Agent 可能包含 UI、会话管理、Skill 加载、MCP 工具、文件系统、模型服务。不能只把它归类为“AI Agent”；应分别覆盖模块行为及完整任务链路。

## 测试层级

- 单元/组件：最小代码或功能单元。
- 组件集成：组件之间的交互。
- 系统集成：不同系统/服务之间的交互。
- 系统测试：完整系统是否满足需求。
- 验收测试：是否满足用户/业务验收条件。
- 端到端：从用户入口到最终业务结果的完整链路。

选择适用层级，并说明测试范围。没有必要每个对象都覆盖全部层级。
