# 测试设计方法库

根据对象和风险选择方法，不要机械地把所有方法应用到每个项目。

## 一、黑盒测试

### 等价类划分
将输入划分为预期行为相同的类别，每类选择有代表性的值。
- 有效类：符合规则的输入。
- 无效类：缺失、类型错误、格式错误、超范围或不允许的输入。
- 每个等价类应说明分类依据。

### 边界值分析
围绕边界及其相邻值设计测试。
- 最小值、最小值附近、正常值、最大值附近、最大值。
- 对长度、数量、金额、日期、文件大小、分页、超时等尤其适用。
- 边界由需求、配置或代码约束决定；未知边界标记待确认，不要编造。

### 判定表测试
当多个条件共同决定结果时，列出条件组合及对应动作。
- 识别条件、条件取值、结果动作。
- 合并不影响结果的冗余组合。
- 优先覆盖高风险组合。

### 状态迁移测试
适用于订单、任务、登录会话、审批、安装、上传等有状态对象。
- 列出状态、触发事件、允许迁移和禁止迁移。
- 测试合法迁移、非法迁移、重复事件、并发事件和恢复路径。

### 场景测试
从真实用户目标出发，覆盖完整操作流程。
- 主成功路径；
- 替代路径；
- 中断与恢复；
- 用户取消或修改；
- 依赖失败后的结果。

### 组合测试
多个参数、角色、设备或配置共同影响行为时使用。
- 优先使用成对/组合覆盖减少组合爆炸。
- 对高风险组合进行全组合或定向组合。
- 记录未覆盖组合及理由。

## 二、白盒测试

### 语句覆盖
验证可执行语句是否被执行。不能证明所有分支均已测试。

### 分支覆盖
验证每个判定结果的不同分支（如 True/False）是否执行。

### 条件覆盖
验证复合判定中的各个布尔条件是否分别取到 True 和 False。

### 路径与异常路径
识别关键执行路径、循环边界、异常捕获、资源释放、提前返回和清理逻辑。

### 数据流与资源生命周期
检查变量定义/使用、文件句柄、网络连接、锁、临时文件、事务等是否正确管理。

**证据限制：** 仅阅读源代码只能提出覆盖建议，不能声称实际覆盖率。真实覆盖率需要测试执行及覆盖率工具报告。

## 三、经验型测试

### 错误猜测
结合技术特点和常见缺陷推导风险，例如：
- 空值、零值、负数、超长字符串；
- 重复提交、重复执行、重复文件；
- 时区、编码、精度、浮点误差；
- 并发更新、超时、断网、权限不足；
- 缓存过期、状态残留、会话切换。

### 探索式测试
在测试过程中根据新发现的行为调整后续测试。记录测试思路、操作、观察结果和发现。

### 检查清单测试
根据对象类型使用专项检查清单，避免遗漏高频风险。

### 缺陷反推
从已知 Bug 反推：
1. 最小复现条件；
2. 触发该缺陷的输入/状态；
3. 相邻边界和变体；
4. 相关模块影响；
5. 修复后的回归路径。

## 四、方法选择规则

- 需求/功能说明：黑盒方法为主，结合经验型测试。
- 有源码/脚本：黑盒 + 白盒 + 经验型。
- 有状态流程：状态迁移 + 判定表 + 场景测试。
- 多参数输入：等价类 + 边界值 + 组合测试。
- AI Skill：场景、语义变体、多轮状态、规则断言、人工/模型辅助评估。
- 安全/性能：按专项方法设计，不能用普通功能用例代替。

输出中说明关键方法及其适用理由；不必罗列所有理论名词。
