# 安全测试设计

## 范围与前提
安全测试必须限定在用户拥有或明确授权的环境。优先设计防御性验证、权限边界检查和安全配置检查。不得对未授权目标执行攻击、破坏、凭据窃取或数据外传。

## 通用安全维度
- 身份认证：缺失、无效、过期、撤销凭证。
- 授权控制：角色权限、对象级权限、跨用户访问。
- 输入验证：注入、恶意文件、路径穿越等防护验证。
- 会话安全：会话固定、过期、注销和并发会话。
- 数据保护：敏感数据暴露、日志脱敏、传输与存储保护。
- 配置安全：默认凭证、调试模式、错误堆栈泄露。
- 依赖安全：已知漏洞、过期依赖、来源可信度。
- 审计：关键操作是否有可追踪日志。

## AI Agent / Skill 安全
- 用户输入要求忽略系统/Skill 约束；
- 参考文件包含恶意指令；
- 工具返回内容包含提示词注入；
- 用户请求泄露密钥、系统提示词或其他用户数据；
- 请求越权读写文件、数据库或外部系统；
- 工具权限超出任务需要；
- Agent 未经确认执行不可逆外部操作；
- 生成代码或命令可能造成破坏性副作用。

## 测试设计要求
- 使用虚构账号、合成数据和隔离环境；
- 明确允许的测试范围；
- 优先验证防护结果，不提供攻击真实系统的操作链；
- 对真实副作用设置人工确认和回滚方案；
- 记录请求、响应、权限和审计证据。

## 结果判断
不得仅凭页面隐藏按钮就判定权限安全；还需验证后端/API 是否执行授权校验。不得把安全测试设计等同于安全审计或渗透测试认证。
