# 功能与业务逻辑测试

## 测试目标
验证功能行为、业务规则、角色权限、状态变化及数据结果是否符合需求。

## 场景清单

### 核心功能
- 正常输入和主成功路径。
- 不同合法输入及可选参数。
- 核心计算、规则和结果。
- 用户取消、返回、修改和重复操作。

### 业务规则
- 必填、选填、默认值和字段联动。
- 多条件组合及优先级。
- 不同用户角色、会员等级、组织或状态。
- 金额、数量、折扣、日期、配额等计算。
- 规则冲突、规则变更及历史数据影响。

### 状态和流程
- 合法状态迁移。
- 非法状态迁移。
- 重复提交或重复触发。
- 中断、恢复、撤销和超时。
- 并发操作导致的状态竞争。

### 数据
- 保存、读取、修改、删除。
- 前后端展示一致性。
- 刷新、重新登录、跨设备后的持久性。
- 空数据、大数据量、重复数据。
- 失败时是否部分提交或产生脏数据。

### 负向与异常
- 缺失字段、非法值、类型不匹配。
- 用户无权限、对象不存在、对象已失效。
- 依赖服务不可用。
- 网络中断、重复请求、超时。
- 错误提示是否准确且不泄露内部信息。

## 用例编写要求
- 一个用例聚焦一个主要验证目标。
- 复杂业务流程可拆成多个用例，但保留必要的端到端用例。
- 预期结果必须对应明确业务规则。
- 对未定义的规则标记“待确认”，不要自行假设。
