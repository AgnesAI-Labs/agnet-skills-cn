# 风险分析与测试优先级

## 1. 风险分析

风险可按以下因素判断：
- 影响：发生后对用户、业务、数据、安全或合规的影响；
- 可能性：缺陷出现的可能性；
- 暴露面：受影响用户、功能或调用频率；
- 可发现性：问题是否容易被发现；
- 可恢复性：失败后能否恢复，是否可逆。

可采用定性高/中/低，或经用户确认后采用风险评分。没有足够数据时不要伪造精确概率。

## 2. 测试优先级

- P0：核心链路阻断、严重数据损坏/泄露、越权或高影响安全风险。
- P1：重要功能错误、关键业务结果错误、主要异常流程失效。
- P2：一般功能、边界、兼容或次要流程问题。
- P3：低影响体验、文案或轻微展示问题。

## 3. 风险优先测试顺序

通常优先：
1. 核心业务主链路；
2. 数据完整性和不可逆操作；
3. 权限、安全和隐私；
4. 关键外部依赖及失败恢复；
5. 高频使用路径；
6. 新增或近期变更模块；
7. 历史缺陷及用户反馈；
8. 低频边缘体验。

## 4. 测试优先级与缺陷严重程度的区别

- 测试优先级：应该先执行哪条用例。
- 缺陷严重程度：缺陷出现后影响有多大。

高优先级用例不一定会发现高严重程度缺陷；两者分开记录。
