# 测试用例专家（Test Case Expert）

面向软件测试与质量验证的通用 Skill。它先识别被测对象、测试目标和证据，再按风险选择测试层级、维度与方法，输出可执行的用例、覆盖映射和待确认事项。

## 适用对象

- Web、桌面、移动应用及功能/业务流程
- 代码、脚本、API、数据库与数据处理
- 自动化工作流、插件、MCP、连接器和系统集成
- AI Agent、Skill、提示词及多轮对话流程

## 主要工作模式

生成或补充用例、测试方案设计、用例审核/优化、缺陷复现、回归测试设计、结果分析和上线验收检查。

## AI Agent 与 Skill 专项

按被测 Skill 实际声明设计测试，涵盖触发与负向边界、功能完整性、指令遵循、工作流、多轮上下文、输入处理、输出质量与格式、工具调用、参考文件、异常、安全、稳定性和兼容性。区分文件静态检查、平台发现/加载、触发行为和核心任务执行证据；对多轮场景提供完整轮次与逐轮检查点，不以一次成功推断稳定。

## 使用示例

- `$test-case-expert 帮我为这个功能设计测试用例。`
- `$test-case-expert 测试一下这个 Python 脚本，重点看输入边界和异常处理。`
- `$test-case-expert 帮我测试这个 Skill 的触发和多轮行为。`
- `$test-case-expert 审核这份测试用例，指出重复、遗漏和不可执行项。`
- `$test-case-expert 根据这份执行记录总结测试结果，并归并发现的问题。`

也可自然描述目标，例如“上线前帮我看看这个流程还要检查什么”。纯知识问题会直接解释，不强制进入用例生成。

## 用例数量

首次未指定数量时先给 10 条高价值用例。已有用例后，用户要求“再多一些/全面一点”且未指定数量时扩展到 30 条总量；指定数量优先。“补充 N 条”表示新增 N 条。用例按风险和对象特征分配，不为凑数重复场景。

## 文件结构

- `SKILL.md`：触发、工作流程、数量规则和质量边界。
- `references/`：测试对象分类、设计方法、领域专项指南及方法来源参考。
- `templates/test-case-template.md`：通用用例结构。
- `templates/test-case-skill-template.md`：AI Skill/Agent 专项字段与多轮表格。
- `templates/test-result-summary-template.md`：测试执行结果与问题归并报告。
- `templates/test-case-example.json`：通用 JSON 示例数据，不是 JSON Schema，也不等于特定执行器格式。
- 其他模板：覆盖矩阵与用例审核报告。

## 调用和材料

将整个 `test-case-expert` 目录放入目标 Agent 支持的 Skills 目录，并保留 `SKILL.md`、`references/`、`templates/` 的相对关系。提供需求、代码、接口文档、Skill 包或现有用例时，可直接从材料开始分析；只有会影响正确性、执行条件或授权范围的关键信息缺失时才追问。

真实代码执行、应用操作、API 调用或外部副作用取决于目标宿主提供的工具、权限和测试环境。用例设计不代表已经执行；实际结果需要可核验证据。不同宿主、模型和版本分别验证。
