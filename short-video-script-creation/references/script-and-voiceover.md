# 脚本与口播写作规范

## 1. 脚本基本原则

脚本是视听内容的执行蓝图，不是单纯的文字稿。每段内容都要考虑画面、声音、信息和时间。

建议脚本结构：

1. 基本信息：主题、目标、受众、类型、时长、风格；
2. 创意概念：一句话说明视频如何呈现；
3. 内容结构：各段落的任务与顺序；
4. 正式脚本：时间/段落、画面、动作、台词/旁白、字幕、声音、时长；
5. 制作备注：场景、人物、道具、素材和待确认事项。

可使用 Markdown 表格，也可根据剧情或复杂度使用场景分段。不要为了表格化牺牲可读性。

## 2. 口播语言

- 优先使用日常语言和具体动词；
- 一个句子尽量表达一个主要意思；
- 重要概念先说人话，再补充专业术语；
- 适当使用例子、对比和场景；
- 避免连续堆叠形容词和抽象口号；
- 不为追求口语化而大量添加“然后、其实、就是说”等填充词；
- 允许根据人物设定调整语气，但保持自然和可信。

## 3. 口播与画面分工

不要让旁白把画面已经展示的内容重复说一遍。可采用：
- 画面展示过程，旁白解释原因；
- 画面展示结果，旁白讲述背景；
- 画面提供细节，字幕标出关键数据；
- 人物对白推动关系或剧情，环境声增强真实感；
- 屏幕录制展示操作，旁白解释关键步骤。

## 4. 时长估算

时长需要综合：
- 字数与实际语速；
- 停顿、呼吸和情绪表达；
- 产品操作或演示耗时；
- 镜头观察和转场留白；
- 片头片尾与字幕阅读时间。

中文口播约 180–240 字/分钟可作为初步估算参考，不是硬性标准。讲解、故事、情绪表达和快速口播会有明显差异。对严格时长任务，应给出预计区间，并建议实际朗读计时。

## 5. 事实、表达与占位

- 用户未提供的产品数据、价格、功效、案例、荣誉、评价不能自行补充。
- 使用“可帮助”“适合”等表达也应有事实基础，不能变相承诺效果。
- 需要补资料时使用清晰占位，例如 `[待补充：产品实际续航数据]`。
- 故事创作可以虚构人物和事件，但若用于真实品牌或纪实表达，应明确虚构设定。
- 对比、测评和体验结论应标明条件与依据。

## 6. 示例：脚本行写法

**不合格：**  
镜头 1：展示产品。旁白：这是一款非常好的产品。

**更可执行：**  
镜头 1（约 3 秒）：桌面近景，人物将产品放在使用场景中，镜头保持稳定，焦点落在产品操作区域。旁白：“每天整理这些文件时，我最常遇到的问题是……”屏幕字幕同步显示核心问题。声音以现场环境声为主。

第二种写法仍需根据具体产品和素材进一步细化，不能将示例中的场景当作真实产品事实。
