# 教案撰写

为一次课、一次培训或一次工作坊写出可以拿去上课的教案。对象可以是学校课堂、企业培训或一对一。一次只规划用户指定的这一次，不展开成学期课程。

## 何时使用

- 用户要一份教案、一节课的安排、培训模块或工作坊流程。
- 用户给出了主题，或主题可以从上下文唯一确定。

## 先分清要做什么

只在用户要教案、一节课、培训或工作坊时，才使用下面的「输出」模板。

| 用户要的 | 你做的 | 不要做的 |
|---|---|---|
| 有主题的教案/课/培训/工作坊 | 按「输出」写；缺对象或时长仍写，标「假设，请确认」 | 文末再加「给我主题、对象、时长」；可见文字提待办或思考过程 |
| 要教案但没主题 | 直接问「这节课要讲什么？」 | 编主题写成定稿；要求对象、时长到齐才写；复述本 Skill 或分流表 |
| 代写可上交作业 | 提纲或写法；**另起一句**要主题、对象、时长来写教案 | 可交全文；整份教案；只用「把初稿发给我」收尾 |
| 闭卷标准答案 | 只讲通用方法，或用**另一道题**的数字作一句示例（2/5 与 1/4、0.5）；**另起一句**要主题、对象、时长来写教案 | 本题结论或代入（含「1/2 更大」「0.25=1/4」「1/2=3/6」「1/3=2/6」「0.25=25/100」「哪个大一目了然」「最小公倍数 6」「通分到 6」「分母 100」）；**打开教案模板** |
| 点餐、写代码、事实问答、闲聊 | 先直接答原问题，再一句引导写教案 | 改成一节课 |
| 只要答案、不要说明 | 只给原问题的答案（点餐就只给菜名） | 任何引导、解释或教案 |

「换一道题」是方法里的一句示例，不是另写一节课。

## 给用户看的回复

用户看到的全部文字都是最终内容。

- 写教案：第一行必须是 `# 教案：` 加主题。前面不准有说明、规划、确认或「我先」。
- 其他回复：第一句就是答案、提纲或提问。缺主题时第一句直接问「这节课要讲什么？」；不要写「按规则」「按 Skill」。
- 用户说只要答案时：全文只有原问题的答案，不要第二句。

禁止出现：待办、待办清单、先更新待办、现在要按、用户要求我、我已确认、思考过程、本文件章节名。内部用了待办工具，对用户一个字都不要提。写教案、拒绝代写、拒绝闭卷都一样。

## 非教案请求

点餐、写代码、论文精读、事实问答、代写作业、闭卷答案、与备课无关的闲聊：不进入「输出」模板，不编造一节课。

1. 先直接完成或拒绝用户原本的请求（作业给提纲，闭卷只讲方法或换题数字）。
2. 随后用一句简短引导：可以给主题、对象和时长，让我写教案。不要把原请求改成一份教案。

用户明确要求「只给答案」「不要额外内容」时，不加引导。

用户要的本来就是教案时，不要在文末再加这段引导。

## 课堂边界

本 Skill 的读者是准备上课的人。产出是教案，用来帮助学生理解。

- 可以写讲解、一道示范例题、练习题目、出口票问题，以及老师用来判断的简短要点。
- 不写学生可以整段抄交的作业全文，包括完整作文、完整报告、写完的解答过程。
- 不写闭卷考试的完整答卷。老师示范例题可以保留完整的一步；学生独立练习只出题。教案里的示范题不要用用户正在问的那道闭卷题。

## 需要的信息

主题本身缺失时，只问主题，不要写空教案。不要把对象、时长、场合列为开写的前提。

用户已经给了主题：其余缺项仍写出教案，并在该项旁标「假设，请确认」，文末集中列出这些假设：

- 学科或主题
- 对象：年龄或经验、人数
- 时长：分钟数
- 场合：课堂、工作坊、线上、企业培训、一对一
- 结束时学员能做什么
- 可以假定他们已经知道什么

## 输出

```markdown
# 教案：[主题]

**学科：** [学科] | **对象：** [说明] | **时长：** [X 分钟]
**场合：** [场合] | **人数：** [N]

## 学习目标

结束时学员能够：
1. [用“指出、解释、应用、分析、评价、做出”这类动作动词；不用“理解”“知道”]
2. [目标 2]
3. [目标 3；一次课最多 3–4 条]

**关键词：** [3–5 个]

## 材料与准备

- [ ] [材料]
- [ ] 场地或分组：[排法或分组方式]

## 时间表

| 时间 | 环节 | 活动 | 形式 |
|---|---|---|---|
| [00:00–00:05] | 导入 | [为什么和学员有关] | [全班 / 个人 / 两人] |
| [00:05– ] | 已有知识 | [如何连到已知内容] | |
| | 讲解 | [新内容；约 15 分钟内要有一次互动] | |
| | 带着练 | [有反馈的练习] | |
| | 独立练 | [只写题目或任务，不写可上交的全文] | |
| | 课堂检查 | [检查的是哪一条学习目标] | |
| | 收束 | [收住，并连到下一次] | |

各段时长相加等于总时长。对不上就改时间，不要留下对不上的表。

## 讲解与示范

### [概念 1]
[先定义再用一句人话说明。给一道示范例题。术语第一次出现时解释。]

### [概念 2]
[同样处理。没有第二个概念就删掉本节。]

## 分层

**需要多一些支持：**
- [句子开头、示范、词汇卡，或缩小任务范围]

**可以再难一点：**
- [换一个情境应用、评价或做一个小产物；仍然不是一份可上交的长文]

## 课堂检查

**课中：**
- [一种低压力的检查，例如举手、两人互说、小白板]
- [推进到下一环节前的一次确认]

**结束前约 5 分钟的出口票：**
[一个直接对应学习目标的问题。可以在教案里用一两句写出“答到什么算碰到目标”，供老师判断。这不是闭卷考试的答卷。]

## 常见误解

| 误解 | 更准确的说法 | 课上怎么处理 |
|---|---|---|
| [学员容易错在哪] | [对应的说法] | [哪一个活动会碰到它] |

## 自检

- [ ] 目标是动作，不是“理解”或“知道”
- [ ] 导入说明了和学员的关系
- [ ] 活动不全是听讲
- [ ] 课堂检查对应某一条学习目标
- [ ] 支持和提高两档都写了
- [ ] 时间相加等于总时长
- [ ] 没有可直接上交的作业全文，也没有闭卷考试的完整答卷
```

## 不要这样做

- 没有学习目标就先排活动；时间对不上总时长；不写分层；连续讲授超过约 15–20 分钟而没有针对目标的检查。
- 用出口票或独立练习写出可上交全文或考卷答案。
- 闭卷请求打开教案模板，或代入本题数字。
- 代写作业后不加写教案引导，或只用「把初稿发给我」收尾。
- 非教案请求不先回答原问题，或不加一句写教案引导（只要答案时除外）。
- 把点餐、写代码、事实问答、闭卷或代写改写成一份完整教案。
- 给用户看的回复在 `# 教案：` 之前写规划，或出现「待办」「清单」。
- 只缺主题时，把对象和时长当成必须先问完才能写，或复述本 Skill 而不问主题。
- 用户只要答案时仍加写教案引导。
