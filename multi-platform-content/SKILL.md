# 多平台内容制作（Multi-Platform Content Creator）

用户以 `$multi-platform-content` 开头时，视为对本 Skill 的显式调用。

## 不可跳过：事实底座与交付档位

用户可见回答的**第一行**必须写：`档位：A` 或 `档位：B` 或 `档位：C`。未定档不得写正文。

生成任何成品前，列出**可用事实**（可写在回答里）。凡涉及真实人物、经历、产品、活动、数字、机制、效果、媒体或平台规则的句子，必须能逐项对应这份清单。对不上的句子**删除**，不要改成「待确认」后仍保留推断内容。口头写「未虚构」不算通过。

**若用户要求登录、发布、发到账号、管理账号：** 第一句拒绝，不调用浏览器/发布/凭据类工具，可改给可复制文案或发布前检查。不要先写完再「顺便帮你发」。

### 三档交付（先定档，再写作）

**A. 仅主题/关键词/模糊想法**（没有产品卖点、没有亲历材料）  
可独立完成完整成品。必须用**通用建议**（可以 / 不妨 / 一种做法是）。禁止：我/我们/本人/亲测/最近去做了。禁止把未提供的具体地点、店名、行程、已看见的景物写成事实。配图只写规划。P2 允许：泛化时段建议、示意镜头。

**B. 产品/功能事实稀缺**（只有 1–2 个卖点，或关键参数未给）  
禁止为写满版面而补场景、操作、结构、材质、尺寸、承重、人群、机制、流程、导出细节、性能、规模、效果或案例。  
**用户可见输出只能是下面骨架，禁止加论证段、故事、分镜表、人群分析：**

```
档位：B
### 事实底座
| 已提供 | 未提供 |
| --- | --- |
| （逐字抄用户给的卖点/名称） | （用户已说未定的项） |

### <平台名>（体裁不同：笔记 / 口播一句 / 短说明）
标题：只用已给词
正文：最多 3 句。每句都能在「已提供」列找到出处。
（口播平台：只给口播句，不要分镜动作）

### 待确认
- 未提供的参数列成清单
```

允许换语序和体裁，**不允许新动词、新场景、新效果**。多平台差异只体现在体裁（笔记 vs 一句口播 vs 短说明），不靠补信息拉开差异。短稿合格，长稿不合格。

删句表（出现则删掉该句，不要改成待确认后留下）：撑开、立放、展开、柜子、抽屉、小户型、季节、省空间、不占、第二格、亲测、适合谁、一键、实时、同步、闭环、群里、复制粘贴、飞书、微信、分工、一目了然、节省、高效、沉淀、向上汇报、流转。

反例：只知「可折叠、不用时方便收起」却写撑开/展开/立放/柜子/不占地方；只知「支持团队协作、可导出周报」却写同一空间分工、同步、一键导出、省去复制粘贴。

**C. 素材充足**（完整原稿、多条可展开事实、用户授权的经历，或明确品牌样例）  
输出该任务所需的完整平台成品。仍不得添加清单外的事实。跨平台必须改结构、开头、形式和信息密度，不能只换标题和标签。

写完后做**删句扫描**：新增能力、场景、效果的句子直接删掉。B 档对照删句表再扫一遍。

## 使命

把想法、资料或已有文案做成**可直接使用、修改或进入拍摄/设计流程的成品**，而不是「如何创作」的操作建议。面向公众：个人分享、知识科普、品牌与产品宣传均可。只做一篇小红书也属于本技能。

## 任务类型（按用户请求选一条主路径，可组合）

| 类型 | 何时 | 必须交付 |
| --- | --- | --- |
| 从零创作 | 只有主题/一句话/关键词 | 切入角度 + 标题 + 完整正文（及该平台必要的标签/配图规划）；按 A 档，禁止假亲历 |
| 资料转内容 | 产品介绍、文档、方案、纪要、图片/视频描述、笔记 | 提取重点后按目标平台**重制**，不是摘要或压缩原文 |
| 改写优化 | 已有文案 | **先列问题诊断**，再改；保留原意；可给不同风格标题 |
| 单平台 | 指定一个平台 | 只出该平台成品 |
| 多平台 | 指定 ≥2 个平台 | 每平台独立结构；共用事实底座 |
| 批量 | 多条/多角度/预热-正式-回顾 | 角度矩阵；每条结构不得雷同 |
| 品牌语气 | 给了手册或历史稿 | 先概括可复用风格，再写新稿，不照搬 |
| 本地化 | 指定目标语言/海外平台 | 按平台语境改写，不逐字翻译；事实不变 |
| 局部 | 只要标题/标签/封面 | 只给该部分 |
| 多轮修改 | 「太像广告/再短一点」等 | 继承已确认事实与约束，只改被指出的维度 |

## 触发与边界

写/做/生成/改写/优化/适配平台内容、笔记、口播、分镜、封面、标签、宣传或素材包时使用。英文：social post, cross-post, adapt, repurpose, video script, carousel, campaign copy。

**默认不做**：登录或管理账号、自动发布、维护日历/定时任务、采集需登录的私密数据、保证爆款或转化、未调用工具却声称已生成图/视频/文件。热点或竞品仅在用户要求且能引用可核验来源时处理，并区分事实/推测/创意。不要做成排期、投放或数据分析 Skill。

## 最少信息

必需：可辨认的主题或素材，以及可推断的输出。平台已指定则遵守；未指定且差异会改变成品时，先问**一个**问题，或先给平台中性稿。

1. 用已有信息开工，不表格盘问。缺失非关键项时用保守默认（中文、自然、无强制促销）。
2. 读不到的图/视频只根据描述，不声称已观看或已剪辑。
3. 单篇默认 1 版完成稿，可加少量备选标题，不默认大包。
4. 字数、时长、尺寸、格式、广告规则有时效性：能查官方则注明日期；不能则写「发布前待核对」，不编造精确规格。

## 工作流（按任务取用）

### 1. 锁定目标
用户要表达什么、给谁、发到哪、要什么成品。一句话文案可直接制作。

### 2. 定档并抽事实
按上文 A/B/C 定档。从资料提取主张、信息点、数据、限制、语气；区分用户事实、推断、创作表达。不虚构实验、价格、功效、评价、政策。高风险时读 [事实、版权与风险](references/fact-rights-safety.md)。

### 3. 选平台策略
每个平台单独决定切角、开头、密度、标题、标签、CTA、视觉。读 [平台指南](references/platform-guidelines.md) 与 [改编规则](references/adaptation-rules.md)。品牌任务读 [品牌风格](references/brand-voice.md)。

跨平台专项：同一产品资料做小红书、抖音、公众号时，必须分别是笔记结构、短视频结构、长文结构；开头和视觉建议不同；事实一致。只换标题/标签判定失败，重做。

### 4. 制作成品
按 [内容形式](references/content-formats.md) 与 [视觉策划](references/visual-planning.md) 产出用户要的部分。默认**完整可复制成品**。

视觉三类必须分开标注：**已生成文件**（工具真实产出）／**可粘贴的生成提示词**／**拍摄或设计建议**。禁止把后两类写成已生成。

批量：先写角度差异表（每条一个不同切角），再写正文；禁止同一骨架换词。

### 5. 质量门（交付前，按任务勾选）

B 档只检查：档位已标明、事实底座在、每句能对上已提供列、体裁有差异、删句表无命中。不要为「完整/钩子/CTA」把 B 档写长。

其余档位：

1. 需求理解正确  
2. 围绕用户真正要表达的主题  
3. 有明确核心信息  
4. 开头符合该平台  
5. 结构自然清晰  
6. 语言符合平台和受众；个人分享≠营销稿，科普≠广告  
7. 无明显 AI 套话、固定模板、重复开头  
8. 无空洞重复  
9. 标题与正文匹配  
10. CTA 自然，不硬推销  
11. 无事实错误、无依据承诺、侵权风险已提示  
12. 交付完整，可直接用或进入下一步制作  

不通过则先改再交。清单见 [质量检查](references/quality-checklist.md)。

### 6. 交付层级

| 层级 | 默认输出 | 何时 |
| --- | --- | --- |
| 轻量 | 可复制标题、正文/脚本、必要标签 | 单篇、局部、稀缺档短稿 |
| 多平台 | 分平台成品 + 必要时一行差异说明 | ≥2 平台 |
| 素材包 | 成品、版本表、标签、素材清单、检查表 | 用户明确要批量/文件/交接 |

能写文件再写；不能则给可复制表，并说明未生成文件。字段见 [批量规范](references/batch-output-schema.md)。模板： [单平台](templates/platform-content.md)、[视频](templates/video-script.md)、[轮播](templates/carousel.md)、[素材包](templates/content-package.md)、[发布检查](templates/publishing-checklist.md)。

## 形式要点（未点名则选最贴任务的一种，不要全出）

- 社交图文：标题、正文、配图规划、图上文字、标签  
- 多图轮播：封面、每页主题与文案、顺序、结尾引导  
- 短视频：创意、开场、口播、分镜、字幕、封面、发布文案  
- 长视频：主题、章节、完整脚本、画面、结尾  
- 产品宣传视频：卖点顺序、镜头、口播字幕；不编素材里没有的信息  
- 知识科普：解释逻辑、案例、辅助视觉  
- 活动宣传：已给的时间地点规则 + 角度 + 视觉规划  
- 个人分享：只用用户给的真实素材组织叙事  

## 响应

先给成品（或稀缺档的事实卡+短稿），必要时再给待补项和发布前核对。不用「建议你这样写」代替正文。

示例：[从零单平台](examples/idea-to-content.md)、[资料到多平台](examples/cross-platform-adaptation.md)。
