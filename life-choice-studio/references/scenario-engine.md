# 情景推演引擎

情景推演的作用是比较条件变化，不是预测未来。只对用户实际正在考虑、且有足够信息描述的路径推演。

## 路径卡

每条主要路径使用下列字段；没有信息时写未知，不补造。

| 字段 | 要问或分析什么 |
| --- | --- |
| 起点条件 | 当前资源、时限、支持、承诺与关键前提；金额未知时写未知，不编造房租或薪资区间 |
| 近期变化 | 接下来数周或数月会发生什么，什么立即失去或获得 |
| 中期分支 | 哪些关键事件会让路径走向不同结果 |
| 较长期可能 | 只描述机制与条件，不许诺结果 |
| 风险与失败条件 | 什么会使路径失效，最早信号是什么 |
| 可逆性 | 能否暂停、退出、回退；退出成本由什么组成 |
| 可控变量 | 用户、他人、环境分别能影响什么 |
| 转向条件 | 出现什么信号时应复盘、调整或停止 |

至少比较“采取此路径”“维持现状/不采取此路径”，必要时再比较过渡试验。没有现实基础时，不强行加第三条路径。

## 三层时间尺度

- **近期**：先发生的现金流、时间、关系、精力、试验结果或直接代价。
- **中期**：近期选择可能如何改变机会、能力、责任、选择空间或压力。
- **较长期**：只讨论可能的路径依赖与条件分支，不用确定结局取代不确定性。

时间尺度由决策类型决定。明天到期的 offer 不要假装能完整推演三年；关系与职业转向也不必承诺精确月份。

## 压力测试

选择最能改变判断的 1–3 项测试，而非机械穷举。

### 事前验尸

假定某路径已失败，追问：失败由哪些前提落空造成？哪些信号会在早期出现？现在能做的低成本防护是什么？

### 反事实

分别查看“没有做这件事会怎样”和“条件 X 改变后会怎样”。反事实必须与用户现实条件相连，不能编造平行人生故事。

### 敏感性检查

寻找一个会令判断翻转的变量，例如经济缓冲、具体岗位职责、关系安全、试验结果或时间窗口。说明当前倾向依赖它，而不是把它藏在结论里。

### 可逆性检查

优先区分可逆的小实验与难逆转的大承诺。可逆不等于没有代价；写出退出会损失的金钱、时间、关系、声誉、机会或精力。

## 行动实验和复盘

行动不是替用户完成决定，而是验证关键假设。一个合格行动应低风险、可观察、可在明确窗口内完成，并能改变后续判断。

可用格式：

> 如果在 [时间窗口] 出现 [可观察信号]，我会 [重新评估/调整/停止]；若没有出现，我会 [下一步]。

不要把提醒、消息、申请、签约或付款说成已经替用户完成。
