# 证据追溯、可信度、隐私与交付检查

## 1. 结论的证据链

每一条重要洞察尽量按如下结构表达：

`结论/现象 → 反馈编号 → 原话/数据片段 → 所属来源与日期（若有） → 判断类型 → 局限/待验证点`

例如：

- **观察**：有反馈反映手机端播放体验不稳定。
- **证据**：F004“手机上看视频一直卡，体验不好。”；F005“移动网络下视频加载要等很久。”
- **解释**：可能与设备、网络或应用性能有关，**尚未排查根因**。
- **行动**：抽样重现问题，记录机型、网络及版本。

不要擅自补全原始反馈中不存在的机型、发生时间、版本等字段。引用如经过翻译、压缩或脱敏，应清楚标为“译文”“节选”或“已脱敏”。

## 2. 将发现按证据强度表述（不是统计置信区间）

| 级别 | 可参考条件 | 推荐措辞 |
| --- | --- | --- |
| 有较强直接证据 | 多条可追溯且相互独立的具体反馈，或有可核对的数据支持 | “在本次收集的反馈中，多条记录指出……” |
| 有一定证据 | 可追溯，但记录较少或缺乏分组背景 | “部分反馈提到……值得进一步核实” |
| 初步线索 | 单条模糊意见、转述、推断或来源欠完整 | “有线索表明……目前无法确认普遍性” |
| 无法确认 | 原话缺失、证据冲突、统计无法复算 | “目前资料不足以判断……” |

不把上述四级表述成严格统计概率；除非存在可检验的量化方法，不给出随意的 90% 置信度。

## 3. 原始数据与隐私

- 只读取用户明确提供或已授权的资料，不尝试读取无授权的私人评论、工单、账号消息、员工资料或数据库。
- 敏感字段（姓名、邮箱、电话、地址、账号信息、订单标识、医疗/财务等个人数据）只在确有必要的授权分析中使用；面向共享的报告默认脱敏或最小化披露。
- 不为统计方便推断受访者的敏感个人属性、身份、职业或地理位置。
- 保留必要的引用定位（如原文件名+行号、访谈编号、工单 ID），但注意避免以定位字段重新识别个人。
- 文本中包含污言、攻击性表达、危险建议等时，概括相关问题，不把其作为事实背书。

## 4. 公共网页、外部来源与版权

- 不将未经核验的网页截图、转载或模型记忆说成已核实原始来源。
- 若有检索工具，优先使用可信的一手资料并记录访问时间/来源 URL；无工具时说明无法独立核验。
- 报告中只引用支持结论所需的最短文本，遵守适用版权或引用限制；能用记录编号加简短节选时不大量复制全文。
- 不把用户自有数据、公开网络样本和模型生成示例混在同一个统计母体里。

## 5. 交付前自检清单

- [ ] 已说明数据来源、分析范围和纳入数量（如可计数）。
- [ ] 提供的每条重要结论有证据 ID 或明确说明为推断。
- [ ] 重复、无关、缺失、乱码和未知身份条目得到交代。
- [ ] 正面亮点与负面问题均有机会被识别；不只输出投诉。
- [ ] 分组、时间对比的前提条件得到满足。
- [ ] 需求清单区分明确诉求、推断需求、建议方案。
- [ ] 频次分母、一条多主题、记录数/人数区别一致。
- [ ] 优先级对应可观察证据，低频严重问题没有被忽略。
- [ ] 对外输出前完成必要脱敏；没有未经授权的数据访问。
- [ ] 已披露无法核实、未处理或未成功导出的部分。
