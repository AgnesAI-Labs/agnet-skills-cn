# 反馈统计、对比、优先级与局限

## 1. 分析前固定口径

应尽可能报告以下信息：

- `N_raw` 原始记录数：输入数据中的独立原始记录数。
- `N_included` 纳入分析的记录数：排除空白、损坏、明显无关等记录后的数量。对排除原因做简短说明。
- `N_dedup` 去重后的记录数（如执行了去重）：说明去重规则；不代表独立人数。
- `N_people` 独立反馈者数：仅当用户标识足以可靠去重时统计，不可从同名昵称猜测。
- `M_theme` 某主题提及次数：同一记录下同一主题通常记一次，多主题可重复计入不同主题。
- `R_theme` 提及该主题的不同原始记录数：按 `反馈编号` 去重计数，适合回答“多少条反馈提到它”。

默认写“12 条纳入分析的记录中，3 条提到播放问题（3/12）”，避免写成“25% 用户受影响”。如果没有可靠的反馈者去重，禁止把记录数称为“人数”。写出分项次数时，声明的合计必须等于各分项相加。样本限制写明之后，不把影响说成大于这些记录。

## 2. 多主题统计例子

- F001：“视频老卡，字幕也模糊” → 性能 1 次、字幕 1 次；总反馈记录仍为 1。
- F002：“卡顿严重” → 性能 1 次；总反馈记录为 1。
- 结果：原始记录 2 条；性能涉及 2 条，字幕涉及 1 条；主题提及次数共 3。主题百分比合计可能超过 100%，必须注明“多标签统计”。

如果源数据中一条记录内部重复提到同一主题，可以记录多次提及作为独立研究指标；**默认统计“包含该主题的记录数”**，只有任务明确要求才逐次计算提及频次。

## 3. 比例与比较

- 某主题的**记录占比** = 提及该主题的纳入记录数 / 同口径的纳入记录数；说明分母和多标签情况。
- 对比两组时分别报告分子和分母：例如 A 组 4/20、B 组 3/10；不得只比绝对数量。
- 不同渠道、不同月份的样本结构若变化很大，报告“本次收集反馈中的变化”，不直接等同总体体验改善/恶化。
- 没有可信的采样框、响应率或母体信息，不能推断用户总体比例，更不应自造统计显著性。
- 小样本（例如每组个位数）以定性解释为主，必要时直接给分子分母，避免夸大百分点变化。
- 对“环比变化”“趋势”至少需要两个可比时间窗的可靠日期；不能把导出时间当作事件发生时间。
- 有缺失时间/渠道/用户类型的条目时保留“未知”组，并在对比中标明排除或保留数量。

## 4. 主题影响和需求优先级

优先级不是仅按出现次数排序。观察以下证据维度：

| 维度 | 判断依据 | 证据不足时 |
| --- | --- | --- |
| 严重程度 | 无法完成核心任务、重大服务中断、一般不便、轻微偏好 | 标“待核实” |
| 覆盖范围 | 有可观察的独立受影响群体、流程或场景 | 不把出现次数当覆盖率 |
| 频次 | 记录数、提及次数、渠道分布 | 仅定性描述 |
| 紧迫程度 | 安全风险、关键流程阻断、强时效性 | 不能编造 SLA 或期限 |
| 可执行性 | 是否已有可验证措施、技术约束、可控资源 | 给出验证步骤，而非虚假成本 |

**建议参考分层（启发式，不是绝对算法）：**

- P0：已有明确证据的重大风险/核心流程完全不可用/潜在安全问题，建议优先核实和升级处理；无证据时不得滥标。
- P1：反复出现且明显阻碍目标的痛点，或虽低频但严重且可信的事件。
- P2：具有一定证据、改善体验或效率的机会，需要小范围验证。
- P3：偏好差异、低影响的优化建议或证据尚弱的想法，进入机会池。

提供优先级时，附一句判断理由和会推翻判断的条件。除非用户提供并授权采用权重/投入数据，不生成“打分 87.5”“预计提升转化 14%”之类的伪精度。

## 5. 针对不同问题的分析方式

| 用户目的 | 优先方法 | 不必强做 |
| --- | --- | --- |
| 快速知道大家在说什么 | 主轴归类、代表原话、正反意见 | 精细统计、复杂优先级模型 |
| 分析商品/内容优缺点 | 优点/问题双列、主题与频次 | 强行给出产品路线图 |
| 提炼访谈需求 | 情境 → 任务 → 痛点 → 诉求 → 假设 | 把 5 人访谈外推总体百分比 |
| 客服工单分析 | 问题类别、阻断级别、解决状态（仅有数据时） | 猜测问题根因已确认 |
| 问卷数据分析 | 单选/多选题统计 + 开放题主题分析 | 不支持的统计显著性结论 |
| 多月趋势分析 | 同口径时间窗、每期分母、变化与可能的收集偏差 | 没有日期时凭印象画趋势 |
| 用户群体对比 | 已知标签交叉分析、不同群体的代表原话 | 凭文字猜测年龄或身份 |

## 6. 稳健性检查

1. 统计结果可否从行级数据复算？
2. 所有比例是否同时写了分子/分母？
3. 是否说明单条反馈多标签导致合计大于 100%？
4. 不同组样本是否可比，是否说明信息缺失？
5. 不满意的人更可能留言、客服样本更偏向问题用户等选择偏差是否被考虑？
6. 是否明确区分“原因假设”与“已确认原因”？
7. 哪些发现可能被另一种分类方案或少数异常样本改变？
