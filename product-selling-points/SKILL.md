# 产品卖点提炼

Agnes 版不创建、导出或声称已生成 xlsx。用户要求表格、xlsx 或文件时，直接按对应模板的表头在对话中给出 Markdown 表；不调用文件导出工具，不提供文件路径，也不把表格说成附件或可下载文件。

「产品事实或特点」和「直接功能」都只放用户原文的连续片段。表格可有一个简短标题，但不要写工具名、路径、JSON、重试、报错、任务清单或下一步。

## 1. 使命与结果

帮助用户回答四个问题：

1. **产品有什么：** 从资料中准确识别功能、特征、参数、服务内容和限制。
2. **对用户有什么价值：** 将产品事实连接到具体需求、任务、痛点和使用场景。
3. **为什么值得选择：** 识别有证据支持的差异化价值、适用条件和竞争短板。
4. **应该怎么表达：** 将价值转化为清楚、可信、适合目标受众与传播场景的表达。

本 Skill 的核心不是把产品描述“写得更好听”，而是建立从产品事实到用户价值，再到营销表达的可追溯链路。

## 2. 触发范围

适用于：
- 实体商品、消费品、耐用品、食品、美妆、家居、数码及其他商品；
- 软件、AI 产品、SaaS、开发者工具、企业解决方案；
- 专业服务、生活服务、课程、知识产品、会员及订阅服务；
- 品牌产品、产品系列、开源项目、内部工具及非商业项目的价值介绍。

典型请求包括：
- 提炼产品核心卖点、优势和购买理由；
- 从功能参数中提炼用户收益；
- 分析不同人群分别应该关注什么；
- 对比多个产品或竞品，判断真正的差异；
- 为官网、商品详情页、宣传卡片、销售介绍、短视频等准备卖点素材；
- 审核现有卖点是否准确、空泛、夸大或缺乏证据。

不要求用户使用固定格式，也不要求每次提供完整资料。

## 3. 执行原则

### 3.1 事实优先，表达其次
- 不得编造产品功能、参数、性能、价格、认证、销量、市场份额、用户评价、竞品信息或使用效果。
- 不把“可能带来”写成“必然实现”，不把推断写成事实。
- 对有条件限制的功能，保留版本、套餐、地区、设备、使用条件等限定信息。
- 不为了凑足卖点数量而制造优势；没有明显差异时，应如实说明。

### 3.2 结论必须可追溯
对关键卖点尽可能标注来源、证据状态和适用条件。区分：
- **已确认事实：** 来源明确且内容直接支持该陈述；
- **资料陈述：** 用户提供或产品宣传材料中有此说法，但尚未独立核验；
- **合理推断：** 从已知事实推导出的潜在用户价值，需要标记为推断；
- **待验证假设：** 需要用户研究、测试、数据或补充资料才能确认；
- **未知/冲突：** 资料缺失、相互矛盾或无法判断。

不能将资料陈述自动升级为已独立验证事实。

### 3.3 用户价值不能只靠形容词
避免只写“高效、智能、便捷、专业、优质、领先”等空泛形容词。应说明：
- 对谁有用；
- 在什么情况下有用；
- 帮助完成什么任务或改善什么体验；
- 价值依据是什么；
- 有哪些限制或前提。

「可直接使用」「推荐照用」「一句话主张」只引用用户原文，不改写。

每一条都写成两行：
- 原文：从用户这次的资料里连续抄出的片段。
- 可用句：只能是上一行原文里的连续文字，可以删掉无关的字，不能换词，不能加动词、手势或体验。

原文是「底座触摸开关」，可用句就写「底座触摸开关」，不能写成「轻触即可操作」。原文是「亮度 5 档」，可用句就写「亮度 5 档」，不能写成「可按需切换」。一句话主张只把这些原文片段用顿号或逗号接起来。

写完后对照。可用句里出现原文那一行没有的词，整句移出可直接使用区。推断可以写，但只能放在单独的「推断，不能直接发布」一节，并且不得再出现在可用句或一句话主张里。

### 3.4 比较必须公平
- 同一维度、相近版本、相同条件下比较。
- 区分“产品有此功能”“竞品未找到相关信息”和“竞品明确不支持”。
- 未查到不等于不存在；资料不全时标记“未知/待核实”。
- 竞品价格、套餐、功能和政策等易变化信息应注明资料日期；需要实时信息且具备检索能力时再查询。

### 3.5 任务深度自适应
- **快速模式：** 用户只要几条卖点或一句话表达时，直接给结论和必要依据，不启动完整报告。
- **标准模式：** 用户要系统提炼时，完成产品拆解、人群/场景匹配、卖点排序和营销表达。
- **深度模式：** 用户提供多份资料、多个竞品或要求完整分析时，增加证据核查、对比矩阵、风险检查和文件交付。

不得为了流程完整而重复询问已经提供的信息，也不得强制生成所有文件。

## 4. 工作流程

### Step 1 — 理解任务与资料
识别产品类型、分析对象、用户目标、目标受众、传播场景、竞品范围和交付形式。
- 优先使用当前对话和已提供文件。
- 资料不完整但仍可分析时，先给初步结论并列出假设。
- 只有缺失信息会实质改变结论时，才提出最关键的澄清问题。
- 用户没有指定受众或渠道时，不要擅自锁定单一人群或平台；可先给通用版本并说明适用假设。

### Step 2 — 建立产品事实底稿
提取并归类：
- 产品名称、类别、版本/型号、地区、套餐或适用范围；
- 功能、规格、材质、组成、服务内容、交付方式；
- 使用条件、限制、依赖、风险、售后或支持信息；
- 已提供的价格、认证、测试、数据、评价及其来源；
- 尚未提供或相互冲突的信息。

保留原始表述与单位，不擅自换算或补齐缺失参数。重要信息记录来源名称、页码/章节/链接或文件位置（可获得时）。

### Step 3 — 从特点推导用户价值
对每项可能重要的特点，建立链路：

**产品事实/特点 → 直接功能 → 用户任务或问题 → 潜在收益 → 使用场景 → 证据/验证方式**

推导时检查：
- 这项功能实际解决什么问题？
- 哪类用户会在什么场景下重视它？
- 用户收益是否由产品事实合理支持？
- 是否依赖额外条件、用户行为或外部系统？
- 是否有证据支持效果程度？

没有足够信息时，只描述可支持的直接价值，不推断具体节省时长、提升比例、收入增长或效果保证。

### Step 4 — 分析用户、人群与场景
根据用户提供的用户研究、评论、访谈、销售反馈或业务背景识别：
- 用户类型与任务；
- 使用触发点和高频场景；
- 当前替代方案及不便；
- 购买/采用动机；
- 主要顾虑、阻力和不适用情况。

没有用户证据时，可以提出“待验证的潜在人群/需求假设”，但不得伪装成调研结论或声称某群体普遍如此。不要仅凭年龄、性别等标签刻板推断需求。

### Step 5 — 竞品与替代方案分析（按需）
当用户提供竞品资料或明确要求对比时：
1. 确认比较对象、版本、地区、套餐和资料日期。
2. 建立对所有对象一致的比较维度。
3. 区分相同点、不同点、优势、短板和未知项。
4. 识别差异是否对目标用户有实际意义。
5. 对关键差异注明来源与证据状态。

竞品资料不足时，先输出可比较部分，不要自行填空。替代方案可以包括人工流程、线下服务、现有工具或“不采取行动”，不局限于直接竞品。

### Step 6 — 筛选与排序卖点
优先判断卖点是否：
- 对目标用户重要；
- 对应明确的任务或场景；
- 有可理解的用户收益；
- 与同类产品存在有意义的区别；
- 有足够证据支撑；
- 能被清楚、简洁地表达。

需要量化排序时，可使用 1–5 分的启发式评分，默认参考权重：
- 需求相关性：25%
- 用户价值清晰度：20%
- 差异化程度：20%
- 证据强度：25%
- 场景适配度：10%

评分仅用于辅助排序，不代表客观市场测量。每项分数必须有简短理由；证据缺失时降低证据分并标记待验证，不得用高总分掩盖重大证据缺口。若样本和资料不足，优先采用“高/中/低 + 判断理由”，不要制造精确感。

将结果区分为：
- 核心卖点：最值得优先传达的价值；
- 辅助卖点：补充说明、增强信任或覆盖次级需求；
- 人群/场景专属卖点：只对特定受众或场景成立；
- 基础信息：必要但缺乏区分度的产品事实；
- 待验证机会：值得研究但暂不能作为确定宣传主张的方向；
- 不建议使用：证据不足、表达误导、差异不成立或风险较高的主张。

### Step 7 — 转化为营销表达
按任务需要生成：
- 一句话产品价值主张；
- 核心卖点标题与解释；
- 功能特点到用户利益的通俗表达；
- 不同人群/场景版本；
- 不同渠道或篇幅版本；
- 证据支撑、适用条件和必要限定；
- 可选的行动引导语。

表达应具体、自然、易理解。根据受众调整专业程度和语气，但不得通过夸张、恐惧、虚假稀缺、绝对化承诺或伪造社会认同来增强说服力。可直接使用的句子先按第 3.3 节逐词核对，再交给用户。

### Step 8 — 核验与交付
交付前逐项检查：
- 每个事实性主张能否追溯到资料；
- 推断和假设是否清晰标记；
- 是否遗漏重要限制条件；
- 竞品比较是否同口径；
- 是否存在绝对化、保证性或无法证明的表述；
- 卖点是否真正对应用户利益；
- 每条可用句是否都是对应「原文：」行里的连续文字，没有换写成轻触、按需切换或其他原文没有的说法；
- 推断是否只出现在「推断，不能直接发布」，并且没有被抄回推荐句；
- 不同输出之间是否矛盾；
- 文件是否真实生成、可打开、字段完整。没有文件时，用户看到的第一条就是「文件没有生成。」，前面没有重试说明。

## 5. 输出规范

根据任务选择输出，不强制每次生成全部文件。

### 5.1 产品卖点分析表（Markdown）
以 `assets/selling-points-template.xlsx` 的 `卖点矩阵` 表头为结构，在对话中给出 Markdown 表。该表固定字段为：
产品/版本、产品事实或特点、直接功能、用户问题/任务、潜在用户收益、目标人群、使用场景、卖点类型、优先级、证据状态、来源、限制条件、判断说明、待验证事项。

### 5.2 差异化价值对比表（Markdown）
以 `assets/differentiation-template.xlsx` 的对应表头为结构，在对话中给出 Markdown 表。建议字段：
比较维度、我方产品、竞品A、竞品B、差异说明、对用户的意义、证据来源、资料日期、证据状态、待核实事项。
应包含竞品概览和结论摘要；没有竞品资料时不生成虚构对比。

### 5.3 营销表达素材.md
根据任务需要包含：
- 产品一句话介绍；
- 核心价值主张；
- 核心/辅助卖点；
- 卖点标题、解释和证据；
- 人群与场景版本；
- 渠道适配表达；
- 不建议使用的表达及替代说法；
- 待补充资料与验证建议。

### 5.4 待验证信息清单
记录待验证主张、缺失证据、潜在风险、建议验证方式、优先级。没有待验证事项时无需生成空文件。

### 5.5 文件交付规则

用户要求表格、xlsx 或文件时，不执行文件写入或导出。按对应模板的列顺序直接给出 Markdown 表；数据从表头下一行开始，说明文字不写进数据区。可以在表格后给一段遵守第 3.3 节的简短摘要，但不得声称存在文件、路径、附件或下载结果。

「产品事实或特点」和「直接功能」只粘贴用户原文的连续片段。没有独立检测的规格，证据状态写「资料陈述」，不写「已确认事实」；厂商标注的承重保持厂商标注。原文未提供的内容仅可在「判断说明」以「推断：」出现。不得把 Markdown 表说成已经生成的 xlsx，也不得声称已经完成用户未要求或环境不支持的外部发布、投放、调研或竞品监测。

## 6. 参考资料使用

按需读取以下文件，不要每次无差别加载全部参考资料：
- `references/product-analysis.md`：产品事实提取和价值链分析；
- `references/audience-value.md`：用户、人群与场景；
- `references/differentiation.md`：竞品和替代方案对比；
- `references/marketing-expression.md`：表达策略与素材组织；
- `references/quality-check.md`：证据、风险和交付验收。

- `differentiation-template.xlsx`

## 7. 与其他 Skill 的协作

本 Skill 负责上游的产品价值识别与卖点定义。用户进一步要求完整内容制作时，可将已确认卖点交给相应能力继续完成，例如：
- 小红书笔记创作；
- 多平台内容制作；
- 短视频脚本创作；
- 电商视觉策划与文案；
- 产品介绍页/官网文案；
- 市场调研与竞品分析。

交接时应同时传递卖点、目标受众、场景、证据来源、限制条件和待验证项，避免下游内容把假设扩大成事实。

## 8. 最终行为要求

- 先解决用户的实际问题，再决定是否需要完整分析或文件。
- 不把流程当作固定表单；根据资料和任务调整步骤。
- 结论明确，理由可追溯，未知项坦诚标记。
- 允许得出“没有足够证据证明独特优势”的结论。
- 不以卖点数量、文案华丽程度或文件数量代替分析质量。
