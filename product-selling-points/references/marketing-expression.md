# 营销表达与卖点素材组织

## 1. 表达原则

- 先讲用户关心的结果或任务，再补充产品如何做到。
- 具体优先于形容词，证据优先于口号。
- 使用目标受众理解的语言；必要时解释技术术语。
- 保留重要条件、适用范围和限制。
- 不同渠道可以改变篇幅和语气，但不能改变事实。
- 不默认使用夸张、制造焦虑、绝对化或虚假稀缺表达。

可直接使用的句子只连续引用用户原文，不改写。原文是「底座触摸开关」，可用句就写「底座触摸开关」，不写成「轻触即可操作」。原文是「亮度 5 档」，可用句就写「亮度 5 档」，不写成「可按需切换」。换写放进「推断，不能直接发布」，不要抄回推荐句。

## 2. 基础表达结构

### 一句话价值主张
面向【目标用户】，在【具体场景】中，产品通过【已确认的能力/特点】，帮助用户完成【任务/收益】。

只有在信息充分时才填满所有部分；不确定项应保留为待确认，不要自行补写。

### 单条卖点
- **卖点标题：** 简短、具体、易理解；
- **用户价值：** 对用户有什么实际意义；
- **产品依据：** 哪项功能/参数/服务支持该价值；
- **适用人群/场景：** 对谁、何时有用；
- **证据与限制：** 来源、条件、注意事项。

## 3. 常见表达转换

| 原始表达 | 问题 | 优化方向 |
|---|---|---|
| 功能强大 | 没有说明强在哪里 | 具体说出支持的任务和能力范围 |
| 操作便捷 | 缺乏场景 | 说明减少了哪些操作步骤 |
| 智能高效 | 空泛且可能夸大 | 说明自动完成哪一步，哪些仍需用户确认 |
| 品质卓越 | 缺乏证明 | 使用可核实的材质、工艺、测试或服务事实 |
| 行业领先 | 需要充分比较证据 | 改为准确描述已确认的产品特点 |

## 4. 按渠道调整表达

根据用户指定渠道适配；没有指定时可提供通用版本，不必默认生成所有渠道。

- **官网/产品介绍：** 价值主张、核心能力、适用场景、证据和限制；
- **商品详情页：** 购买决策相关卖点、规格、场景、使用条件和售后；
- **社交媒体种草：** 真实场景、具体体验、适用人群；没有真实体验时不能伪装亲测；
- **短视频：** 开场问题/场景、产品解决方式、关键证据、行动引导；
- **销售介绍：** 客户问题、解决方案、差异、实施条件、证据和异议回应；
- **B2B/SaaS：** 业务流程、部署/集成、角色价值、服务范围、成本和风险；
- **宣传卡片：** 一条清晰主张、简短解释、可验证支撑点。

不要将完整详情页、脚本、社交笔记等下游成品强行纳入本 Skill；用户需要时再交由对应能力完成。

## 5. 多版本表达

只有当不同版本确实服务不同对象或场景时才生成。版本之间应体现：
- 关注点不同；
- 信息深度不同；
- 术语使用不同；
- 证据呈现方式不同。

不要只机械替换“你/企业/用户”等称呼。

## 6. 风险表达替换

发现风险表述时，说明风险原因并给出可用替代句。比如：
- “保证提升 50%” → 若无测试证据，改为描述已确认的功能或测试条件；
- “行业唯一” → 若无全面、及时的比较证据，改为具体说明产品自身特点；
- “所有人都适合” → 改为明确适用人群和不适用条件；
- “用户一致好评” → 仅在有可靠评价样本和口径时使用，并说明范围。
