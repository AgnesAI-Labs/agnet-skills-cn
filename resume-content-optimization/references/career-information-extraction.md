# 用户经历挖掘与事实台账

## 不止读取简历

在用户提供并授权使用的范围内，可读取简历、项目说明、工作总结、周报、绩效材料、作品集、公开项目和数据记录，挖掘简历中未被表达出来的真实贡献。

## 经历记录结构

经历类型、组织 / 项目、岗位 / 角色、起止时间、背景、目标、职责范围、个人行动、使用方法 / 工具、协作对象、交付物、结果、证据来源、事实状态、待确认事项。

## 追问方向

- 你具体负责哪一部分？
- 当时要解决什么问题？
- 你采取了哪些关键行动？
- 其中哪些是你独立完成，哪些由团队共同完成？
- 最终交付了什么？
- 有没有真实数据、反馈、作品或文档可以佐证？
- 如果没有数字，工作覆盖范围、复杂程度或交付物是什么？
- 这段经历与你想投递的岗位有什么关联？

每次只追问影响简历质量的关键问题，避免机械填表。

## 事实等级

已提供 / 有材料支持 / 合理归纳 / 待确认 / 未提供。

简历要点必须能追溯到来源。合理归纳不得扩大事实边界。冲突信息保留差异并向用户确认。

## 量化规则

数字必须有定义、周期、对象、范围和来源。用户只记得大概范围时，需明确标注为用户估计，并征得确认；不能把估计写成精确指标。

无数字时可用范围、复杂度、交付物、流程、问题解决和协作贡献体现价值，不强迫量化。
