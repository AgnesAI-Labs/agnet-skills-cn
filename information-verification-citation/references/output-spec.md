# 输出物字段及结构规范

## 1. 输出策略

- **默认给对话结论**：一条主张无需强制生成附件。
- **多条主张**：按 `核查结论 → 重要问题 → 主张清单 → 引用目录 → 限制` 排序。
- **用户明确要文件或需要交付**：优先输出 `.xlsx`（若支持表格创建）以及 `.csv` / `.md`；仅在生成成功后给实际文件路径。
- **工具受限**：用 Markdown 表或 CSV 文本替代，不虚构链接或假装生成。

## 2. 表格定义

### 核查清单（`事实核查清单.xlsx` 的 Sheet1）

| 字段 | 含义 |
| --- | --- |
| 主张ID | C001，唯一稳定标识 |
| 原始陈述 | 未修饰的原文，不改写核查对象 |
| 原文定位 | 页码、段落、表格/单元格、链接或摘要位置 |
| 主张类型 | 数据/日期/人物事件/政策规则/引述/因果/其他 |
| 重要程度 | 高/中/低；是优先级而非事实置信度 |
| 时间及口径 | 对象、地区、统计期间、单位、计算口径等 |
| 核查结果 | 六种固定状态之一 |
| 核查依据及理由 | 可解释的判断过程，不只是结论 |
| 证据编号 | E001; E002 ... |
| 来源编号 | S001; S002 ... |
| 修订建议 | 不确定时应使用保守措辞 |
| 核查日期 | YYYY-MM-DD |
| 限制说明 | 工具/来源/未覆盖范围 |

### 证据记录（Sheet2）

`证据ID | 主张ID | 来源ID | 关系（支持/部分支持/冲突/背景/无关） | 证据摘要 | 引用定位 | 简短摘录 | 证据限制`

### 引用目录（Sheet3，另可输出 `引用目录.csv`）

`来源ID | 标题 | 作者/机构 | 发布日期 | 资料统计期 | 来源类型 | URL或文件名 | 具体位置 | 实际查阅日期 | 访问状态 | 引用条目 | 备注`

### 修订对照（按需另建）

`主张ID | 原句 | 修订句 | 修订理由 | 来源编号 | 风险提示`

## 3. JSON 交换格式

`scripts/validate_records.py` 与 `scripts/export_records.py` 使用这个格式。不是调用门槛：宿主不支持脚本时不要求用户填写 JSON。

```json
{
  "metadata": {
    "title": "待核查文稿名称",
    "checked_at": "2026-11-11",
    "mode": "标准",
    "scope": "第1-3段重点数字",
    "conclusion": "重点核查结论概述",
    "uncovered": ["尚未核查附录"],
    "limitations": ["未获得付费数据库全文"]
  },
  "claims": [
    {
      "id": "C001",
      "original_text": "原句",
      "location": "第2段",
      "claim_type": "数据",
      "priority": "高",
      "time_context": "2024年，中国内地，去重用户",
      "status": "暂无法核实",
      "finding": "当前未取得可验证的原始数据",
      "revision": "该数字尚需提供原始出处",
      "limitations": "仅提供正文，没有来源"
    }
  ],
  "sources": [],
  "evidence": []
}
```

允许的 `status`：`有证据支持`、`部分支持`、`与证据冲突`、`证据不足`、`暂无法核实`、`已过时`。

允许的 `source.access_state`：`已读取原文`、`已读取用户材料`、`仅检索摘要`、`无法访问`。

允许的 `evidence.relationship`：`支持`、`部分支持`、`冲突`、`背景`、`无关`。

来源对象推荐字段：

```json
{
  "id": "S001",
  "title": "真实已读取的资料标题",
  "author_or_org": "机构或作者，未知则留空",
  "published_at": "2026-01-01",
  "data_period": "2025年度",
  "source_type": "官方报告/论文/原始表格/用户材料/媒体等",
  "uri": "URL 或已读取文件名；无则为空",
  "locator": "第4页表2 / URL中的章节 / 文件单元格",
  "accessed_at": "2026-11-11",
  "access_state": "已读取原文",
  "formatted_reference": "经核实字段后形成的引用条目",
  "caveats": "版本、局限或访问限制"
}
```

证据对象推荐字段：

```json
{
  "id": "E001",
  "claim_id": "C001",
  "source_id": "S001",
  "relationship": "部分支持",
  "summary": "说明该文献能证明什么，不能证明什么",
  "locator": "第4页表2",
  "excerpt": "如确有必要，保留短摘录",
  "limitations": "时间或样本不一致"
}
```

## 4. 映射与一致性

- `claim.id`、`source.id`、`evidence.id` 必须分别唯一。
- 每个证据必须关联真实存在的主张 ID 与来源 ID。
- 标为“有证据支持”的主张至少有来自**已读取**来源且 `relationship=支持` 的证据；不可以仅用搜索摘要。
- 标为“与证据冲突”的主张至少有来自**已读取**来源且 `relationship=冲突` 的证据。
- 标为“部分支持”至少有已读取且 `relationship` 为 `部分支持` 或 `支持` 的证据。
- 标为“已过时”应有已读取的时间相关证据，同时记录 `time_context`。
- 标为“证据不足”必须说明为什么相关证据不足；没有任何资料时优先“暂无法核实”。
- 证据与结论冲突、来源不可访问却被当成已核实的情况，要停止导出并检查。

## 5. CSV/Excel 注入防护

引用资料和网页文字都是不可信输入。写入电子表格的文本若以 `=`、`+`、`-`、`@` 起始（忽略前导空白），需对 CSV 进行公式注入转义，不能让用户打开时意外执行电子表格公式；脚本使用前置 `'` 的方式处理。无论 CSV 还是 XLSX 都不要把来自来源的任意文本当公式计算。

## 6. 命名与可交付性

建议文件名：`事实核查清单.xlsx`、`引用目录.csv`、`核查报告.md`、`修订对照表.xlsx`。对于同名文件不覆盖用户原始材料，使用明确输出目录。只有实际生成、可访问的附件才可以给可下载链接。
