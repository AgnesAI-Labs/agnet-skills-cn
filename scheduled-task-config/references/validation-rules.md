# 定时任务配置检查规则

目标：判断配置是否**结构可理解、静态逻辑一致、用户已确认、目标平台是否具备能力**。不能保证真实调度、运行、权限或通知成功。

## 检查等级

| 等级 | 判定 | 处理 |
|---|---|---|
| ERROR 错误 | 已知不合法或逻辑矛盾，如无效日期、时区、必填条件冲突 | 必须修正；标记不可直接交付部署 |
| QUESTION 待确认 | 重要要素缺失/假设未确认、来源未授权、目标平台未知但任务需专有能力 | 保持 `draft`，列出最少的关键确认项 |
| WARNING 警告 | 可能导致额外运行、重复发送、费用或效果差异，如高频无去重、夏令时、月份短缺 | 提醒风险及应对方案 |
| PASS 通过 | 规则格式完整且未发现静态问题 | 只能称“静态检查通过”，不称“已执行成功” |

## 单任务检查清单

1. 名称与目标：非空，任务目的与完成标准可理解。
2. 时区：IANA 标识，可用于实际解释；单次 `at` 需要明确 UTC 偏移，最好核查偏移与 IANA 时区在该日期一致。
3. 时间规则：按 `kind` 检查必填字段；`HH:MM`、星期（`MO`—`SU`）、月日 1—31、Cron 格式、间隔正数。
4. 月份缺日：`day_of_month` 29/30/31 应有 `missing_day_policy`，否则 QUESTION。
5. 日期与运行窗口：`start_at`、`end_at` 顺序正确；一次性任务已过期则 WARNING / QUESTION，不偷偷改日期。
6. 指令可独立执行：有数据来源、时间窗、步骤、预期输出和失败条件；缺失影响实际运行时 QUESTION。
7. 输入与权限：检查路径/连接器来源是否指定、必要授权是否落实；不能从文字推断真实访问权限。
8. 通知：渠道是否存在；没设置渠道不能默认“会发到手机”。
9. 重试：多次重试必须考虑副作用和幂等性；不可把 `max_attempts=3` 理解为“首次 + 重试 3 次”。本模型定义为**包含首次执行的总尝试次数**。
10. 错过与重叠：核查是否需要补跑；任务可能运行很久时确认 `overlap_policy`。
11. 平台：是否已识别支持哪些调度方式、暂停/重试/通知字段；未知情况下标为未验证。
12. 密钥：禁止将真实密码、令牌等明文写在任务 JSON 和执行指令里；用安全引用。
13. 不完整草案：允许字段缺失并列入 `open_questions`；不得将其标记为 ready。

## 任务状态

- `draft`：存在未确认事项，或仅为设计草案。
- `ready_for_manual_setup`：用户确认了核心参数，静态校验无错误和待确认项；**仍需人工在平台创建/启用**。
- `paused`：配置中的期望暂停状态，不代表宿主实际已暂停。

## 批量任务核查

- **时间重叠**：对同一时区、可计算下次执行点的任务检查重叠；若没有预计时长，只能提示“同时触发可能争用资源”。
- **任务重复**：名称、目标和规则近似可标记疑似重复，不能自动删除。
- **依赖顺序**：日报应晚于上游数据生成；未知上游完成时间需确认。
- **资源冲突**：同一文件覆盖、相同外部写入、并发配额和接口限流。
- **通知风暴**：高频失败重试的通知频率、升级条件与抑制策略。

建议批量输出表字段：`任务名称 | 规则 | 时区 | 目标平台 | 状态 | 问题等级 | 检查项 | 证据/字段 | 修正建议 | 是否待确认`。可生成 XLSX 时输出 `配置校验表.xlsx`，否则在对话给出表格或 CSV。

## 可执行的离线基础校验

`scripts/validate_task.py` 使用 Python 标准库，检查字段类型与枚举、时区、时间、日期、Cron 基本格式、任务状态和若干安全冲突。它**不会联网、不会创建任务、不会访问连接器**，也不能检查平台专有能力；请再做人工核查。
