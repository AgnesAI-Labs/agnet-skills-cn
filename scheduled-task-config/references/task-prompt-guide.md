# Agent 定时任务指令编写规范

定时任务的提示词必须能在**未来任意一次独立会话**中自行理解；不得假设当前聊天的暂时上下文或未授权的个人文件仍可访问。

## 六段式指令

按需选用，不要机械冗长。

1. **角色与目标**：一两句话交代任务结果。例：“你是每周运营周报整理者，目标是输出可核查的进展汇总。”
2. **时间窗与基准**：在每次运行时计算，例如“以实际执行时的 Asia/Shanghai 时间为准，分析上一自然周周一 00:00—周日 23:59”；避免写死本次日期。对于轮询，明确采用“过去 24 小时”还是“距上次成功执行以来”（后者须有可靠运行状态）。
3. **资料来源与权限**：指定文件、目录、连接器或公开信息来源；没有访问权限时明确失败输出，不虚构读取内容。
4. **执行步骤与判断标准**：检索/筛选/去重/比对/组织/核验。与任务目标相关的标准优先，避免通用空话。
5. **结果交付格式**：内容结构、排序、长度、文件类型、指定路径（仅在有可写工具和权限时）、必要引用或证据链接。
6. **异常与安全策略**：源不可用/无数据/超时/数据冲突如何标注；不编造事实；涉及外部发布、删除、支付等操作先要求批准。

## 每次执行提示词模板

```text
任务名称：<名称>
任务目标：<本次运行要完成的具体结果>

执行时区与时间窗：<IANA 时区；以本次运行时刻计算的明确时间范围>
输入与授权：<来源、资源路径或连接器、只读/写入权限；未授权时停止相关步骤>
步骤：
1. <获取必要资料；不可用则如何处理>
2. <处理与质量检查>
3. <生成结果>
输出：<固定的内容结构、格式、交付位置；缺失时如何标注>
完成标准：<成功的可检验条件>
异常处理：<无数据、不确定信息、部分失败、重复结果如何处理>
权限边界：<需要人工确认的副作用操作；不得虚构读写成功>
```

## 典型专项建议

- **新闻/舆情/调研**：每条保留来源链接、发布时间及事件实际时间；去重；区分事实和推测；没有新内容时明确无更新。
- **周报/月报**：说明从什么记录提取，按什么周期统计；没有记录就输出缺失清单，不虚构成果。对首次运行要求补历史数据。
- **定时提醒**：提醒文本简单直接，注明渠道是否由平台实际支持。Skill 不直接发送。
- **定期文件整理**：使用允许路径，默认先预览变更；删除、覆盖和搬移须用户授权，建议支持回滚。
- **状态监测**：阈值定义要明确（绝对值/环比/同比）、数据延迟与检查频率；避免重复通知。基于对比变化的条件任务需要状态存储或上次运行结果。

## 优化已有任务的次序

1. 查看现有计划与指令；有执行记录才据此定位失败/低质量环节。
2. 核对数据源和权限是否真实可用。
3. 检查日期窗口、重复执行、缓存/历史状态要求。
4. 细化输出与验证标准，减少不必要冗长指令。
5. 说明具体修改及效果预期，不声称未经测试已改善结果。

## 反例与修正

反例：`每天帮我看看新闻，写得专业点。`

较好：`每日 Asia/Shanghai 08:00 运行时，搜索过去 24 小时内与【指定主题】相关的公开新闻。优先官方发布与原始来源；每条输出标题、事件发生时间、来源、链接及一句影响判断，去重后最多 8 条。如无足够可信新闻，明确写“暂无核实更新”，不得编造链接。` 

注意：“每天 08:00”属于调度字段，执行指令内部的时间窗仍应以**本次实际运行时间**为基准。
