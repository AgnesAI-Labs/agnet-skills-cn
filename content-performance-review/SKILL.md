# 内容效果分析与复盘

## 1. 核心目标

把用户提供的内容数据、内容素材、用户反馈和业务目标，转化为**可追溯的效果评估、内容诊断、复盘结论与可验证的优化行动**。

本 Skill 不是单纯的数据统计器。它需要帮助用户回答：

1. 内容完成了什么目标，效果如何？
2. 不同平台、主题、形式、账号、活动或周期之间有哪些差异？
3. 哪些内容表现较好或较弱，数据证据是什么？
4. 结合真实内容素材，哪些内容特征值得关注？
5. 用户在评论、反馈或行为中表达了什么需求？
6. 下一步具体调整什么，用什么指标、样本和周期验证？

**核心工作链路：数据检查 → 目标与指标匹配 → 效果评估 → 内容/反馈诊断 → 复盘结论 → 优化行动 → 后续验证。**

## 2. 适用任务与路由

识别用户真正要解决的问题，选择一个或多个模式。模式可组合，不要求用户使用固定术语。

| 模式 | 典型需求 | 主要分析重点 |
|---|---|---|
| 单篇内容诊断 | 为什么这条笔记/视频/文章表现如此？ | 单篇指标、内容素材、表现环节和改进点 |
| 批量内容复盘 | 分析最近 10/30/100 条内容 | 分层、主题/形式比较、共同特征和反例 |
| 跨平台对比 | 同一内容在多个平台效果如何？ | 指标口径映射、平台内分析、相对表现 |
| 账号/周期复盘 | 复盘一周、一个月或一个季度 | 目标达成、趋势、内容结构和阶段变化 |
| 活动/营销复盘 | 一次推广或营销活动是否有效？ | 活动目标、渠道贡献、内容表现、线索/转化 |
| 转化分析 | 哪些内容带来点击、线索、注册或购买？ | 可关联的转化路径、归因窗口、成本和质量 |
| 互动/反馈分析 | 用户评论在讨论什么、需要什么？ | 反馈主题、态度、问题、需求和代表性原话 |
| 内容实验复盘 | 新标题/封面/结构是否更有效？ | 实验设计、样本可比性、差异和结论强度 |
| 定性内容复盘 | 只有文案、脚本、图片或视频素材 | 内容价值、受众匹配、表达、结构和待验证问题 |
| 连续复盘 | 对照上期行动和本期数据 | 行动进度、指标变化、假设验证和下一轮计划 |

## 3. 输入识别与澄清

### 3.1 可接受输入

- Excel、CSV、表格、平台导出文件；
- 平台后台截图、数据面板截图或人工整理的数据；
- 内容链接、标题、正文、图片、视频、字幕、脚本或素材说明；
- 评论、问卷、访谈、客服记录、社群反馈；
- 业务目标、统计周期、指标定义、历史数据、目标值、投放和归因信息。

### 3.2 不要求用户一次性提供完整数据

先从用户描述、上传文件和上下文中识别：分析对象、决策问题、目标、平台、周期和可用证据。只有缺少的信息会实质影响分析正确性时才追问，一次只问最关键的问题。

若目标不明确，可先做探索性分析，但必须说明主指标是根据可用字段选择的探索性指标，不代表用户 KPI。

### 3.3 输入不足时

- 只有内容素材：做定性诊断，列出需要数据验证的判断。
- 只有数据没有素材：做数据表现分析，不推断标题、画面、脚本或选题原因。
- 只有截图：只使用可辨认的数据，标注识别不清的字段，不补造数据。
- 没有历史基准：使用本批样本内部比较，不编造行业平均。
- 指标口径不明：保留来源字段，标记待确认，不擅自统一分母。
- 样本较小：可以给观察，但降低结论强度，不把样本规律泛化。

## 4. 标准执行流程

### Step 1：明确复盘问题

明确本次分析要支持的决策。例如“提升互动”与“通过内容获得有效注册”不是同一个目标。区分内容目标、传播目标和业务目标，避免用播放量替代转化目标。

### Step 2：读取数据与素材

读取所有相关文件和工作表，不要只看文件名或首个工作表。识别内容 ID、平台、账号、主题、形式、发布时间、统计日期、观察窗口、指标和内容素材字段。

对大文件可以先抽样检查结构，但正式指标计算必须覆盖完整可用数据；如果只能抽样，必须标注样本范围，不得把样本结果写成全量结果。

### Step 3：运行定量分析脚本（有结构化数据时优先执行）

当用户提供 CSV/XLSX/XLSM，且运行环境具备 Python 与脚本执行能力时，**必须优先使用本 Skill 自带的分析脚本完成字段盘点、数据检查、指标计算和基础交付**，不要只靠目测或语言模型心算关键数字。

1. 先阅读 `scripts/README.md`，确认脚本依赖和参数。
2. 需要先了解结构时运行 `profile_content_data.py`；它只做字段盘点，不代替正式分析。
3. 选择与用户目标相符的 `--goal`：
   - `awareness`：触达/曝光；
   - `views`：播放/阅读；
   - `engagement`：互动；
   - `traffic`：点击；
   - `conversion`：线索/注册/购买/转化；
   - `revenue`：收入；
   - `auto`：探索性选择，不代表用户 KPI。
4. 如果用户明确指定主指标，使用 `--primary-metric` 传入原始列名；如果用户提供单条内容目标值，可用 `--target-value`，并按目标方向选择 `--target-direction higher|lower`。不得把单条内容目标值误当成账号或活动总 KPI。
5. 一个任务涉及多个文件时，可一次传入多个文件；如果 Excel 中有多个工作表，默认自动识别内容数据工作表，必要时使用 `--sheet`。
6. 运行 `analyze_content_performance.py` 后，必须打开并检查生成的工作簿、报告和行动清单；不能只看到脚本成功退出就直接交付。

示例：

```bash
python scripts/profile_content_data.py 内容数据.xlsx --output 分析输出/数据盘点.md
python scripts/analyze_content_performance.py 内容数据.xlsx --goal engagement --output-dir 分析输出
python scripts/analyze_content_performance.py 平台A.csv 平台B.xlsx --goal conversion --output-dir 分析输出
```

脚本会生成 `内容表现分析表.xlsx`、`运营复盘报告.md`、`优化行动清单.xlsx` 和 `analysis_manifest.json`。脚本负责可重复的定量计算、数据质量检查和基础文件生成；它**不会自动完成深层语义分析、视觉理解、评论主题归纳或因果归因**。这些是 Agent 必须继续完成的工作。

如果当前环境无法执行脚本或缺少依赖，不得声称已经运行。改用可用的表格/数据工具完成计算，或清楚说明限制；不要因为脚本不可用而停止所有可完成的分析。手工计算与脚本计算适用同一条合计复核规则。

### Step 4：数据质量与口径核查

在下结论前检查并记录：

- 空值、重复行、重复内容 ID、错位列、异常值、负数和无法解析的数字；
- 百分比与普通数值是否混用，货币单位是否一致；
- 每条内容的统计时间、发布时间和观察天数是否一致；
- 数据是当日新增还是累计快照，是否可能重复累加；
- 是否混有自然流量、付费投放、达人合作、不同账号或不同活动；
- 指标分子、分母、单位、归因窗口和去重规则是否明确。

完全重复行可以在明确记录规则后从计算样本排除，但原始数据必须保留。相同内容 ID 的多行不能直接删除：它可能代表多平台分发、多次快照或重复导出，必须先判断数据粒度。

### Step 5：建立指标与评价方式

先选主指标，再选辅助指标和护栏指标。只计算分子、分母和统计范围均可确认的衍生指标。

- 传播/触达：曝光、触达、展示频次；
- 消费/观看：播放、阅读、独立观看、平均观看时长、完播；
- 互动：点赞、评论、分享、收藏、互动人数/互动总量；
- 行为：点击、主页访问、关注；
- 转化：线索、注册、购买、收入；
- 效率：CPM、CPC、CPA、ROAS（需成本和归因数据）。

互动率必须标明分母，例如按触达、按曝光或按播放计算；不同分母的互动率不得合并。分母为 0 或缺失时应标记无法计算，不能写成 0%。平台自带比率与自行计算比率要分开标识。

### Step 6：完成多层定量分析

根据任务选择相关维度，不必机械输出全部分析：

1. **整体表现：** 总量、均值、中位数、分布、目标达成和变化幅度；爆款可能扭曲均值，必要时同时呈现中位数。
2. **内容分层：** 高表现、常规、待优化内容。优先在同平台、同内容形式、相近观察窗口的组内分层；说明样本数和分层规则。
3. **维度拆解：** 平台、账号、主题、内容形式、活动、自然/付费、受众、发布时间等。
4. **趋势分析：** 区分发布日期趋势、统计日期趋势和内容生命周期；累计快照不可直接求和。
5. **漏斗分析：** 仅当各环节可以关联到同一内容/用户群和归因窗口时，分析曝光→观看→互动→点击→关注/线索→注册/购买。
6. **转化效率：** 同时看绝对量与转化率、线索/订单质量、成本和退款等护栏，不以单一点击量判断商业价值。
7. **异常分析：** 定位变化发生在哪个指标、平台、主题、账号或内容组，给出需要核验的原因线索。

### Step 7：完成内容素材诊断（不可只看数字）

只要用户提供了标题、正文、图片、视频、字幕或脚本，就必须抽取有代表性的高表现和低表现样本，结合真实素材进行分析。至少考虑：

- 受众与需求：目标人群、场景、痛点和知识水平；
- 选题：主题、具体程度、时效性、差异化和系列关联；
- 标题/封面/开场：价值承诺、问题、冲突、结果前置、信息准确性；
- 结构与节奏：信息顺序、论据、案例、转折、镜头/段落推进；
- 信息价值：实用性、可信度、独特性、完整性和可执行性；
- 表达：语言、语气、节奏、故事性、信息密度；
- 视觉/声音：封面、画面、字幕、镜头、声音和可读性（仅在素材可访问时）；
- 行动引导：CTA、互动问题、链接、转化入口和承诺兑现。

每个关键内容判断必须指向具体内容 ID、标题、原文、时间点或画面证据。不要根据播放量反推封面好坏，不要在只看到标题时分析视频剪辑和画面。若内容文件无法读取，说明缺失，不做假设。

脚本中的文本结构特征（标题字数、数字、疑问句、清单、CTA 词等）只能作为描述性线索。Agent 需要进一步判断语义与上下文，不能把“含数字”直接等同于标题有效。

### Step 8：分析评论与用户反馈

用户提供评论、访谈、问卷或社群记录时：

1. 说明来源、时间范围、样本量和筛选方式；
2. 归纳主题，如需求、问题、认可点、疑虑、误解、反对意见和建议；
3. 按样本内频次统计主题，必要时标注情绪/态度，但不把情绪标签当成客观事实；
4. 保留少量匿名代表性原话，避免泄露个人信息；
5. 将反馈主题与对应内容及效果数据关联（能关联时）；
6. 明确评论样本不代表全体受众，频次不等于总体用户占比。

### Step 9：形成有证据的诊断结论

每条重点结论采用“发现—证据—解释—限制—业务影响”的结构，并区分：

- **事实/直接观察：** 数据或素材直接显示；
- **重复出现的模式：** 在多个可比样本或周期中出现；
- **可能原因：** 与现象相符但尚未排除其他解释；
- **待验证假设：** 有依据但仍需设计验证；
- **无法判断：** 当前证据不足。

不把相关性写成因果关系，不把同期发生写成内容带来的结果。检查投放、发布时间、账号体量、内容生命周期、活动优惠、季节性、平台规则和外部事件等混杂因素。

### Step 10：提出行动和验证计划

建议少而具体，每项行动至少包含：

- 对应问题/机会及证据；
- 具体调整对象和动作；
- 优先级及理由；
- 主要指标、护栏指标和指标定义；
- 验证方式、对照组/对照内容或测试条件；
- 观察周期或建议样本量；
- 继续、调整或停止的判断标准。

优先建议可控、可验证的改动，例如选题角度、标题承诺、开场结构、内容长度、案例密度、CTA、落地页或发布分发。避免“提升质量”“优化标题”这类没有操作细节的建议。没有充分证据时，将建议标记为探索性测试。

### Step 11：连续复盘

用户提供上期报告、行动清单或新一期数据时：

1. 读取上期目标、结论、假设、行动、负责人、状态和验证指标；
2. 使用一致口径对齐新旧数据；
3. 区分已完成、未完成、进行中和无法验证；
4. 判断本期数据支持、削弱还是无法判断上期假设；
5. 记录期间的策略、投放、平台口径或外部环境变化；
6. 更新下一轮行动。

不得擅自覆盖历史数据、已发布记录或旧结论。口径变化必须保留旧值并说明影响。

### Step 12：交付与复核

先检查脚本生成的文件，再补充 Agent 的语义诊断、用户反馈和业务解释。不能把脚本自动生成的基础报告直接当作最终深度复盘。

## 5. 输出规范

### 5.1 轻量分析

单条内容或具体问题优先直接回答：结论、证据、可能解释/限制、最值得尝试的行动。不强制生成文件。

### 5.2 完整分析交付

根据任务需要选择以下交付物，不为凑齐文件而制造空表：

| 交付物 | 内容 |
|---|---|
| `内容表现分析表.xlsx` | 阅读说明、原始数据、标准化数据、指标字典、平台对比、维度分析、发布趋势、内容明细、数据质量、内容特征、行动清单和图表 |
| 内容对比图表 | 趋势、平台内内容对比、主题/形式分组、漏斗或转化图；必须标注范围、单位和口径 |
| `运营复盘报告.md` | 核心结论、分析范围、指标口径、数据质量、整体表现、平台/维度拆解、内容诊断、用户反馈、原因假设、行动和验证计划 |
| `优化行动清单.xlsx` | 发现、证据、动作、优先级、指标、验证方式、观察周期、判断标准、负责人和状态 |

### 5.3 报告表达

- 开头先给 3–5 条最重要结论；
- 每条结论都有数据、内容样本或用户反馈证据；
- 把“发生了什么”和“为什么可能发生”分开；
- 区分总量、单条表现、效率和转化；
- 明确数据缺口、不可比项和待验证问题；
- 建议要对应发现，不输出与分析无关的通用运营建议。

## 6. 指标与平台差异

平台指标定义会变化。涉及具体平台的口径时，优先核对用户提供的官方导出说明或平台官方文档；如具备联网能力且需要确认最新定义，检索官方来源并记录核验日期。社区文章可作为经验参考，不替代官方定义。

跨平台分析遵守：

- 不把不同平台的原始曝光、播放、阅读或互动量直接求和或排名；
- 先在各平台内部按同类内容和相近观察窗口分析；
- 只有定义、单位、分母、时间窗和归因范围可比时，才进行横向比较；
- 需要综合比较时，优先用平台内相对历史中位数、分位或目标达成率，并解释其含义。

## 7. 通用能力边界与非目标

- 仅处理用户提供或明确授权访问的数据；不绕过登录、权限或付费限制。
- 不编造缺失指标、来源、行业基准、用户原话、内容特征或执行状态。
- 没有用户在本次材料中给出的目标或历史值，也没有写明链接和核验日期的平台官方定义时，回答里不出现行业平均、大盘水平、流量池门槛或「优质区间」的任何百分比。搜索摘要、社区文章和代运营经验不算基准，即使页面里写了百分比也不要转述。
- 可直接复制的标题和正文只重组用户已经写出的事实。不加入用户没写的场景、物件、照片内容、时长、故障类型或对话。新角度放在文案外面，标成待验证假设。
- 不把小样本结论泛化为总体用户规律。
- 不把相关性当因果，不承诺爆款、涨粉、传播、收入或转化结果。
- 不自动发布、删除、编辑平台内容，不自动投放广告或修改平台配置。
- 不替代完整市场调研、竞品监测、内容创作、账号管理或长期数据仓库建设。
- 不因脚本可计算某个指标就默认该指标在业务上合理；业务目标和口径仍需核实。

## 8. 工具与降级策略

- 结构化数据优先用脚本/表格工具做精确计算；关键计算必须可复核。
- 有图片/视频理解能力时，分析真实素材；没有时请用户补充可读素材、字幕或文字说明。
- 需要平台定义时优先查官方文档；不能访问时说明未核实。
- 如果无法生成某种文件，提供可用替代形式并说明限制。
- 不声称已经运行脚本、读取文件、联网核验或生成文件，除非实际完成。

## 9. 最终验收门槛

交付前逐项核对：

- [ ] 分析问题与用户业务目标一致；主指标选择合理。
- [ ] 已读取完整可用数据；抽样结果未冒充全量。
- [ ] 数据质量、重复、缺失、异常、单位和观察窗口已检查。
- [ ] 指标公式、分子、分母、单位和口径清楚；零分母不输出 0%。
- [ ] 不可比平台数据未直接混算或跨平台原始值排名。
- [ ] 高低表现分层在可比组内完成，并说明样本数与规则。
- [ ] 有内容素材时已做真实内容诊断；没有素材时未臆测内容原因。
- [ ] 有评论/反馈时已分析主题、频次和代表性原话，并说明样本限制。
- [ ] 事实、模式、可能原因、假设和未知事项有清晰区分。
- [ ] 建议具体，包含验证指标、方式和观察周期。
- [ ] Excel、图表和报告数值一致，文件可正常打开。
- [ ] 连续复盘时核对了上期行动和指标，没有覆盖历史记录。
- [ ] 每个分组的触达、曝光、播放和互动合计都等于纳入该组的各条相加；对不上的合计和比率没有写出。
- [ ] 没有用户基准或官方定义时，回答中没有行业百分比。
- [ ] 可复制文案没有用户未提供的情节。

任一关键项未满足时，不得宣称“完整验收通过”；需在交付说明中指出缺口及其影响。

## 10. 交付前必须停下核对

在写出任何平台、主题或分组的合计、均值或比率之前：

1. 列出纳入该组的内容 ID，并排除已标明的完全重复行。
2. 把这些内容的触达、曝光、播放和互动总量分别相加。互动总量先按单条把点赞、评论、分享、收藏相加，再对单条求和。
3. 分组比率只用这个合计除以对应分母。分母为 0 时写「无法计算」，不写 0%。
4. 相加结果与准备写出的数字不一致时，删掉该合计和由它算出的比率，改写「这组合计未核对」。
5. 重复行按原始行数说明。两行完全相同就写「2 行中保留 1 行」，不把行数说成 3。
6. 回答里只保留核对完成后的一版数字。不写试算过程、划掉的合计，也不留两套互相矛盾的总数。
7. 不同平台的触达、曝光、播放和互动不要加进同一行「全部」合计，也不要由此计算一个跨平台比率。
8. 判断标准里的阈值必须和对照数同一方向。不能把低于对照值的百分比写成「高于该对照」。写不清就删掉这个阈值。

没有可靠基准时，用一句话说明不能和行业平均比较，然后只比较本次给出的内容。用户要求登录、发布、删除或修改平台内容时，停止该动作，并说明需要用户自己在平台上完成。
